# strata.build-task

## 概要

タスクを一つ実行します。タスクに付属する仕様を読み、一つのレイヤー内で指名されたファイルだけを変更し、検証コマンドを実行して、証拠と制約ごとの遵守状況を添えて完了を報告します。

## 使う場面

strata.order のタスクファイルが割り当てられたとき、またはユーザーが計画された変更の実装を求めたとき。タスクなしでは使いません。不完全なタスクは、足りない項目を列挙して差し戻します。

## 手順

1. タスクを読み、完全であること(レイヤー、ファイル、制約、検証)を確認します。証拠: チェックリスト。不完全なら差し戻します。差し戻す場合も、指定されたファイルとそれが指す文書は先に読み、欠けている決定を選択肢と推奨付きの具体的な問いとして挙げます。読むことは推測ではなく、実装することが推測です。続いてオーダーを確保します(`python3 -m kb order claim <order-id>`)。別のマシンやセッションが確保していれば止まって人に尋ねます。証拠: 確保の出力。
2. 指名されたファイルと、同じパターンの既存の例を一つ読みます。証拠: パス。
3. タスクが振る舞いを追加する場合は、まず失敗するテストを書き、次に最小限のコード、それからリファクタリングの順で進めます。証拠: 前後のテスト出力。
4. タスクの検証コマンドとレイヤーチェッカーを実行します。証拠: 出力と終了コード。
5. 報告します: 変更したファイル、制約遵守の表、証拠、検証していないこと。

## 言い訳と反論

| 考え | 反論 |
|---|---|
| 「タスクはほぼ完全だから、残りは推測できる。」 | 推測はレイヤーを越える原因になります。差し戻して、足りない項目を求めてください。 |
| 「テストはコードの後でもよい。」 | 失敗するテストは、そのテストが何かを検査している証拠です。 |
| 「チェッカーの警告は誤検知だ。」 | 理由を添えて警告として報告してください。黙らせてはいけません。 |

## 警告サイン

- タスクに指名されていないファイルの編集。
- コマンド出力のない報告。
- 理由なしに遵守済みとされた制約。

## 検証

- 検証コマンドの出力が報告に入っている。
- レイヤー内のファイルだけが変更された。
- 制約遵守の表が完全である。
