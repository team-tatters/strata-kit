# strata.kb-update

## 概要

現状の形(as-built)の知識をコードと一致させ続けます。変更された各パスを所有するドキュメントを見つけ、出典を付けてその場で更新するか、変更不要の理由を記録し、そのうえで生成ビューを再生成します。

## 使う場面

カバーされているコードが変更された後、ゲートや負債の通知が出たとき、または依頼があったとき。理由を添えて doc_change: none を宣言する場合もここで行います。それも有効な結果です。

## 手順

1. 変更されたファイルを列挙し、covers を通じてそれを所有するドキュメントを特定します。証拠: 対応表。
2. 各所有者について、該当するセクションをその場で更新し、updated と sources を設定します。証拠: 差分。
3. 所有者のいないパスについては、形のドキュメントを作るか、covers を拡張します。証拠: 新しい対応表。
4. 形が変わらなかったところには、理由を添えて doc_change: none と書きます。証拠: その宣言。
5. インデックスを再構築し、リンクチェックを実行します。証拠: 出力。

## 言い訳と反論

| 考え | 反論 |
|---|---|
| 「コードの変更は内部的なものだから、ドキュメントには影響しない。」 | ならば、その理由で doc_change: none を宣言してください。ゲートが必要とするのは仮定ではなく宣言です。 |
| 「ドキュメントは次のセッションで更新しよう。」 | 次のセッションは何が変わったかを知りません。今更新するか、宣言してください。 |
| 「日付のスタンプで十分だ。」 | 内容の確認を伴わないスタンプは、日付が付いたドリフトです。 |

## 警告サイン

- カバーされているパスが変更されたのに、更新も宣言もないこと。
- sources なしで更新されたドキュメント。
- 手で再生成されたノードページ。

## 検証

- 対応表が完全である。
- インデックスとリンクチェックが通る。
- 宣言には理由がある。
