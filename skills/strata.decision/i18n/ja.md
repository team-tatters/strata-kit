# strata.decision

## 概要

アーキテクチャ上の決定を、決定した同じセッションのうちに、decision writer で永続的なレコードとして記録します。決定がこのプロジェクトを超えて一般化できる場合は、推奨カードの候補を抽出します。

## 使う場面

長く効く選択がなされた、または見つかったその時点。後の変更が契約に触れずに覆せるような、局所的な実装上の選択には使いません。

## 手順

1. 決定を一文で、その理由と検討した代替案とともに述べます。証拠: そのテキスト。
2. topic、decision、reason、affects を指定して decision writer を実行します。検討した代替案は一つずつ --alternative '代替案: 採らなかった理由' で、参照した概念・資料は --background で渡し、後の振り返りで選ばなかったものが見えるようにします(DEC-2026-10-30-03)。証拠: DEC id と再生成されたインデックスのパス。
3. 以前のレコードを置き換える場合は supersede を、撤回する場合は withdraw を実行します。証拠: CLI の出力。
4. 決定が一般化できる場合は、カード候補(claim、strength、evidence = この DEC)を backlog に起草します。証拠: 候補のパス。
5. DEC id をハンドオフの decisions_made に入れます。

## 言い訳と反論

| 考え | 反論 |
|---|---|
| 「セッションの最後に記録しよう。」 | セッションは突然終わります。コマンド一つなので、今記録してください。 |
| 「自明だから、誰もレコードを必要としない。」 | 次のセッションはあなたではありません。レコードはその人たちのためのものです。 |
| 「インデックスは直接編集できる。」 | インデックスは生成物です。手で編集した内容は上書きされ、レコードも失われます。 |

## 警告サイン

- DEC id のない、チャット上だけで述べられた決定。
- 手で編集されたインデックス。
- 置き換え済みのルールが、今も現行のものとして引用されていること。

## 検証

- 返信に DEC id がある。
- インデックスが CLI で再生成された。
- ハンドオフの decisions_made が更新された。
