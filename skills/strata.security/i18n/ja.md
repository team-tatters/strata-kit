# strata.security

## 概要

コアは運用者に一日一枚のノートを渡します。新しく出たもの、まだ開いているもの、閉じたもの、誰も見ていない対象。このスキルはそのノートの人側です。定期ジョブが書いたものを読み、人の判断をファイルに戻し（オーダー・受容したリスク・しきい値・リンク）、人が新しい実測値を持ってきたら対象リストを作り直します。自分では収集も格付けもパッチもしません。収集と格付けは定期ジョブが記録された規則で行い、パッチは条件が成立するときだけ `patch plan`・`patch run` で行います。

## いつ使うか

ノートを読むことが毎日のトリガーです。新しく見守るもの（サーバー・デスクトップ・依存ファイル）が増えたとき、ある脆弱性が自分たちに及ぶか問われたとき、しきい値や受容したリスクを定めるときにも使います。インシデント対応（operator の流れ）と製品自身の欠陥ストアには使いません。

## 手順

1. **その日のノートを読む。** `security/notes/<day>.md` を開く。緊急の行から、次に初出日が記された未対応、次に目のない対象。冒頭に見られなかった層があれば何より先にそれを言う。証拠: ノートのパスと counts 行。
2. **判断する前にリンクをたどる。** 触る項目ごとに `security/matches/<day>.yaml` のレコードと照合を開く: どの識別子で一致したか、どの範囲か、スコアはいくつでどの源（NVD・CNA・ベンダー）か、他の源から埋めた値か。証拠: レコード id と照合 id。
3. **人と一緒に分類する。** 緊急項目には既にオーダーがある（定期ジョブが作り、既定の帰属は infra）。オーダーを見せ帰属だけ問う（`assign`）。勧告は問う: オーダーに上げるか（`promote <match> --by`）、理由と期限を書いて受容したリスクにするか（`accept ... --until --by`）、ノートに残すか。一人で決めない。証拠: コマンド出力。
4. **目のない対象に目を与える。** 対象ごとに告知の場所（GitHub リポジトリ・ベンダーページ）を人に問い、`security/sources.yaml` の手動リンクとして書く。ロックファイルのないリポジトリには必要な SBOM を言う。証拠: manual_links の行。
5. **リストは実測値から作り直し、サーバーからは作らない。** 人が `docker ps`・compose・`dpkg-query`・OS 版を貼ったら、イメージ・版・パッケージ名だけ残し（環境変数・パスワード・ハッシュは除く）、`security/registry.yaml` が指す場所に置き、`python3 -m kb security inventory --project <p> --env <e> --write` で差分を見せる。証拠: 差分出力。
6. **しきい値はコマンドでだけ変える。** `python3 -m kb security grading set --project <p> [--env <e>] threshold <値> --by <人>` — history 行が記録。証拠: history 項目。
7. **パッチは条件が成立するときだけ。** `patch plan <order>` が条件（コード水準・ダウンタイムなし・数分での入れ替え・記録された承諾）を示す。`patch run` は条件なしでは拒む。承諾が要る実行は人の承諾がオーダーに先に記録されていること。証拠: オーダーの計画と実行記録。

## 合理化

| 考え | 反論 |
|---|---|
| 「題名がリモートコード実行だから緊急にしよう。」 | 格付けはスコアと記録されたしきい値から来る。スコアがなければ no-score の勧告。見せるが上げない。 |
| 「KEV にあるから緊急だ。」 | KEV はノートの並び順であり格付けではない（DEC-02）。しきい値未満なら勧告。 |
| 「自分で ssh して版を確かめよう。」 | エージェントはサーバーに入らない。人にコマンド出力をもらう。 |
| 「compose に版があるからそのまま保存しよう。」 | パスワードもある。イメージと版だけ残し、何を除いたか言う。 |
| 「人が忙しいからこのリスクは受容しておこう。」 | 受容したリスクは人のもので、理由と期限がある。ノートに残す。 |

## 赤信号

- ファイルで手で直した格付けやしきい値。
- 期限がない、あるいはエージェントが記録した受容したリスク。
- セッションから実行したサーバーコマンド。
- 秘密を含む compose・環境ファイルが vault にコピーされたこと。
- 名前だけで CVE に合わせた目のない対象。

## 検証

- すべての行動がその日のノートの行または照合 id を指す。
- リスト変更後に `python3 -m kb security inventory --all` が exit 0。
- grading.yaml の history が変えた分だけ増え、accepted-risks.yaml の各行に reason・until・by がある。
- サーバーや製品自身の流れに触れていない。
