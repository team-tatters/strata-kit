# strata.order

## 概述

把已批准的规格转化为一份工单和若干自包含的任务，使执行者无需对话也能完成：每个任务只涉及一个层，文件明确，约束来自注册表，并附有证明完成的命令。

## 适用场景

在 strata.spec 之后，需要拆分工作时。用户要求制定计划时也适用。小型工单（两三个任务、单一关注点）使用内联模式：写出工单，任务的仪式性流程简化为同一文件中的检查清单。

## 流程

1. 阅读规格和 layer-map。证据：路径。
2. 写出工单：目标、从规格复制的验收标准、带依赖关系的任务列表。证据：_order.yaml。
3. 写出每个任务：层、要改动的文件、按范围从注册表筛选出的约束、验证命令、完成标准。证据：任务文件。
4. 如果工单很小，决定采用内联模式并说明原因。证据：工单中的说明。
5. 检查是否有环，以及是否有任务跨越两个层。证据：检查结果。

## 借口与反驳

| 想法 | 反驳 |
|---|---|
| “执行者自己会找出要改哪些文件。” | 计划是写给没有上下文的读者的。写明文件。 |
| “约束反正都在注册表里。” | 把它们筛选进任务。执行者读的是任务，不是注册表。 |
| “改动很小，跳过工单。” | 用内联模式。跳过工单就丢掉了验收标准。 |

## 警示信号

- 某个任务没有指明验证命令。
- 某个任务触及两个层。
- 工单没有验收标准。

## 验证

- 每个任务都有层、文件、约束和验证。
- 没有依赖环。
- 若使用了内联模式，则已说明理由。
