# 스킬

> 이 문서는 원천에서 생성된다 — 손으로 고치지 않는다.

에이전트가 따르는 절차. 각 스킬은 증거 요구로 끝난다.

| 스킬 | 무엇을 하나 |
|---|---|
| `design.brief` (pack) | 사람의 디자인 단계입니다. 문서, 실물, 이미지, 게시물, 화면 — 무엇을 디자인하든 일은 브리프에서 시작합니다: 무엇을 위한 것인지, 누가 보는지, 어떤 매체인지, 어떤 제약이 있는지, 무엇을 참조하는지, 무엇이 참이어야 끝난 것인지. 브리프는 사람의 것입니다. 에이전트는 묻고 받아 적을 뿐, 취향을 정하지 않습니다. 디자인은 사람의 취향과 그것을 표현하는 기법(유리 같은 면, 떠오른 부드러운 그림자, 겹친 테두리와 음영)에 기댑니다. 브리프는 이번 작업이 쓰는 것을 이름으로 적습니다. |
| `design.taste` (pack) | 취향은 에이전트가 고르는 스타일이 아니라 판단의 기록입니다. 이 스킬은 그 기록을 프로젝트 하나나 브랜드 하나마다 둡니다. 사람 전체에 대해 두지 않습니다. 취향은 작업이 놓인 맥락에서 판단되기 때문입니다. 취향 노트는 네 절입니다: 취향(사람이 승격한 줄), 신호(반응과 고름), 추론(에이전트가 짐작한 것, 표시 붙임), 거절(사람이 물리친 것과 그 이유). 서로 다른 브리프 세 곳에서 나온 태그는 승격 후보가 되고, 정하는 것은 사람입니다. 표현 노트는 그 취향이 어떻게 보이는지를 적습니다. 원값(색·흐림·투명도·간격·반경·글꼴)은 한 번만 적고, 기법마다 사람이 읽는 문단과 겹·관계식의 YAML 블록을 둡니다. 관계식 — OKLCH 명도로 밝게·어둡게, 투명도, WCAG 대비 — 은 `kb taste expression` 이 계산합니다. |
| `ideation.shape` (pack) | 아이디어는 완성되기 훨씬 전부터 쓸모가 있습니다. 이 스킬은 사용자가 아이디어를 쓸 수 있는 상태로 정리하도록 돕습니다. 쓸 곳은 기획·명세·결정·회고 어디든 됩니다. 아이디어를 대신 만들지는 않습니다. 아이디어 하나는 노트 한 장이고, 다섯 속성(발단·문제·방법·결과·의미)을 갖습니다. 빈칸은 허용하며, 빈칸이 다음 질문이 됩니다. 에이전트는 아이디어에 아직 필요한 조건과 오더의 수를 예측해 사용자에게 확인을 받습니다. 확인된 수가 그 아이디어의 무게이고, 열린 아이디어 무게의 합이 사용자가 지고 있는 고민의 총량입니다. 아이디어는 제한 없이 키울 수 있습니다. 30일 넘게 발전이 없는 아이디어는 아카이브를 제안하고, 지우지 않습니다. |
| `strata.build-task` | 태스크 하나를 실행합니다. 태스크가 담은 명세를 읽고, 한 레이어 안의 지정된 파일만 바꾸고, 검증 명령을 돌리고, 증거와 제약별 준수 여부와 함께 완료를 보고합니다. |
| `strata.decision` | 아키텍처 결정을 decision writer 로 같은 세션 안에 영속 레코드로 남기고, 결정이 이 프로젝트를 넘어 일반화되면 권고 카드 후보를 뽑습니다. |
| `strata.distill` | 쓴 것이 아니라 배운 것을 업무 vault 에서 개인 코어로 옮깁니다. 업무 쪽에는 후보 기록을, 개인 쪽에는 원래 맥락 없이도 서는 패턴이나 가이드를 다시 써서 둡니다. |
| `strata.handoff` | 다음 세션이 이 대화 없이 이어 갈 수 있는 핸드오프를 씁니다. 무엇을 증거와 함께 끝냈는지, 무엇이 왜 막혀 있는지, 어떤 결정을 기록했는지, 무엇을 주의할지, 무엇을 개인 코어로 증류할지. 그 뒤 기록·검증·게시를 세 단계로 나눠 합니다. |
| `strata.init-wizard` | 마법사는 권고 카드로부터 프로젝트의 지침을 조립합니다. 코드가 답할 수 없는 것만 묻고, 프로필 감지 규칙으로 스택을 진단하고, 근거와 함께 카드를 제안하고, 사용자가 승인하면 어댑터를 생성하고, 결과를 검증합니다. 코어 revision 이 바뀌었을 때 재생성하는 길이기도 합니다. 승인된 제안에 적힌 경로 밖에는 아무것도 쓰지 않습니다. |
| `strata.kb-update` | as-built 지식을 코드와 같게 유지합니다. 바뀐 경로마다 소유 문서를 찾아 출처와 함께 제자리 갱신하거나 왜 갱신이 필요 없는지를 기록하고, 생성 뷰를 다시 만듭니다. |
| `strata.order` | 승인된 명세를 오더와 자기완결 태스크로 바꿉니다. 워커가 대화 없이 실행할 수 있도록 태스크마다 한 레이어, 명시적 파일, 레지스트리에서 거른 제약, 완료를 증명하는 명령을 둡니다. |
| `strata.planning` | 기획 단계는 필터입니다. 기획 원문에는 정해지지 않은 이야기와 코드와 규칙이 섞여 있어서, 그대로 주입하면 뒤에 읽는 모두(검색, Onyx 같은 주입 도구, 동료)가 가비지를 읽습니다. 그래서 원문을 바로 요약하지 않습니다. 한 행에 사실 하나로 쪼개고, 모든 행에 행선지를 붙입니다. 주입·공유되는 것은 정리본 — 사람이 관찰할 규칙을 적은 PRD 와 구현이 바뀌어도 유지될 보장을 적은 Logical Tech Spec — 과 결정 기록뿐이고, 원문과 작업 표는 근거로 남습니다. **기획 문서에는 코드와 아키텍처를 쓰지 않습니다.** 테이블, 컬럼, 클래스, 서비스, API 경로, HTTP 코드, 프레임워크, 벤더는 '코드' 행선지로 보내서 명세·오더·결정의 재료로 씁니다. |
| `strata.retro` | 회고는 에이전트의 효율이 아니라 사용자의 이해를 위한 것입니다. 에이전트는 자료를 준비하고 묻습니다. 사용자가 자기 말로 설명하면, 에이전트는 그다음에 기록이 무엇을 말하고 어디서 비어 있는지를 짚습니다. 결과는 사용자가 쓴 노트이고, 방법론이나 결정으로 가져갈 것이 있으면 그것을 맡은 스킬로 하나씩 넘깁니다. |
| `strata.review` | 대화 전체를 공유하지 않고 새 컨텍스트에서 독립된 검토를 받습니다. 결정, 포인터 우선 증거, 범위가 정해진 요청을 담은 구조화 패킷, 한 번의 왕복, 답에 대한 기록된 triage 입니다. |
| `strata.signal` | 운영 단계는 지표를 보입니다. 제품의 흐름을 대신 맡지 않습니다. 지표는 두 가지입니다. strata 자체의 측정(kit 판·세션·검증·핸드오프·git)과, 프로젝트가 이미 가진 흐름 — QA 장부, 커버리지 테스트 케이스 — 에서 읽기만 해서 얻은 제품 흐름 지표입니다. 어느 하나가 나빠지면 이 스킬은 그것을 근거와 함께 노트 한 장으로 남기고 고르는 일을 사람에게 넘깁니다. 그 변화가 무엇으로 이어질 수 있는지와 이유를 보이고, 사람이 고른 것을 기록합니다. |
| `strata.spec` | 변경 하나에 대한 바라는 명세를 만듭니다. 끝났을 때 무엇이 참이어야 하는지를 기준마다 검증할 수 있게 적고, 지금 시스템과 무엇이 다른지를 적습니다. |
| `strata.translate` | 카드·스킬 본문·역할 텍스트·문서의 빠진 로케일을 정본 텍스트와 용어집에서 채웁니다. 의미, 식별자, 구조는 바꾸지 않습니다. |
| `strata.verify` | 완료의 인상을 증거로 바꿉니다. 증거는 테스트·검사기·빌드를 돌리는 순간에 남기고, 완료를 주장하는 순간에 비교합니다. 그 사이에 태스크 파일이 바뀌었으면 증거는 낡은 것이고 명령을 다시 돌립니다. 담당 스킬이 요구한 항목, 각각을 증명하는 것, 검증하지 못한 것을 표로 만들고 진행 가부를 말합니다. |
| `using-strata` | `using-strata` 는 진입점입니다. 두 가지만 하고 다른 일은 하지 않습니다. 세션이 어디에 있는지를 출력해서 사용자와 에이전트가 같은 사실을 공유하게 하고, 작업을 그 작업을 맡는 스킬로 보냅니다. 일을 직접 하지 않고, 이 파일 자체는 바뀌지 않습니다. 확장은 이 파일이 아니라 겹쳐 읽는 레지스트리에서 옵니다. |
