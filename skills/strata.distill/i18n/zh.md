# strata.distill

## 概述

把学到的东西，而不是写出来的东西，从工作 vault 迁移到个人核心：工作侧是一条候选记录，个人侧是一篇重写的模式或指南，脱离原始上下文也能独立成立。

## 适用场景

会话结束时，或出现可复用的内容时应要求提炼。并非每个会话都有候选；“无”并附理由是有效的结果。

## 流程

1. 把经验表述为与项目无关的问题和判断。证据：一句话。
2. 在工作 vault 中写出候选记录：id、来源修订、目标笔记 id、状态。证据：该记录。
3. 写出或更新个人核心的文档：问题、选项与权衡、条件、反例、验证、一个合成示例。证据：该文档。
4. 运行防护检查（名称、领域、路径、附件），并亲自阅读结果。证据：防护检查输出。
5. 把候选标记为已应用；用同一个 id 重新运行时必须更新，而不是重复创建。

## 借口与反驳

| 想法 | 反驳 |
|---|---|
| “直接复制文档就行，已经写好了。” | 复制会带上公司上下文。只重写其中通用的部分。 |
| “防护检查通过了，所以是干净的。” | 字符串检查能抓住名称，抓不住形态。以局外人的眼光读一遍。 |
| “等项目结束时再提炼。” | 经验会淡忘。在学到它的那个会话里提炼。 |

## 警示信号

- 个人核心文档只引用公司路径作为唯一来源。
- 同一个候选 id 对应两篇文档。
- 候选没有目标 id。

## 验证

- 候选记录完整。
- 文档可独立成立；防护检查通过且已被阅读。
- 重新运行是幂等的。
