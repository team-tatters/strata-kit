# design.taste

## 概述

品味是判断的记录，不是代理挑选的风格。本技能为一个项目或一个品牌保存这份记录——从不为整个人保存，因为品味是在作品所处的情境中判断的（DEC-2026-11-01-10）。品味笔记有四个部分：品味（本人提升上来的条目）、信号（反应与选择）、推断（代理的猜测，带标记）、否决（本人拒绝的东西及原因）。出现在三份不同简报中的标签会成为提升候选，由本人决定。表达笔记写明这种品味看起来如何：原语（颜色、模糊、不透明度、间距、圆角、字体）只写一次，每种技法写成一段可读的文字，加一个 YAML 块，列出层和关系——以 OKLCH 明度计的变亮与变暗、不透明度、WCAG 对比度——由 `kb taste expression` 计算（DEC-2026-11-01-11）。

流程的形态取自 skeltonmedia/design-taste-skills（MIT；见本扩展包的 NOTICE；与 Taste Skill 是不同的仓库）：围绕参考的访谈、否决日志、只提升反复出现的信号、推断带标记。这里的文字和检查是 strata 自己的。

## 适用场景

本人在设计并对某样东西做出反应时；项目或品牌需要把品味写下来或重新审视时；某种技法需要写成可检查的形式时。不用于简报本身（design.brief），也不用于产品的 token 或组件契约——那是实现的转换工作。阅读品味笔记是只读；写入信号、推断或技法时升为单会话（DEC-2026-11-01-18）。

## 流程

1. **找到笔记。** 询问这是为哪个项目或品牌。打开它的品味笔记和表达笔记，或提议用扩展包的示例创建；运行 `python3 -m kb taste check <taste.md>` 并展示候选。证据：路径和检查输出。
2. **访谈，一次一个问题。** 对每个参考：你最先注意到什么、其中是什么造成了这种感觉、它是否属于这里。把答案写成信号：`- YYYY-MM-DD 반응|고름 #tag [[brief]] — "他们的原话"`。本人若不是从参考出发，而是从价值出发（品牌的核心价值，或像“信任”这样的词），就以五个维度为框架 — 形状、颜色、感受、质感、物件 — 每个维度问一个联想和一个看得见的线索。本人给出的线索是信号，代理添加的联想是推断。收窄到大约三个互不冲突的关键词，只与本人一起做；两个冲突时，问哪个为主、哪个只占小块点缀（DEC-2026-11-01-13）。证据：新的信号条目，已念给本人确认。
3. **否决。** 本人拒绝某样东西时，问为什么，并写 `- YYYY-MM-DD #tag [[brief]] — "他们的原话" — 이유: …`。没有原因的否决是仍未解决的问题。证据：否决条目。
4. **推断。** 代理从信号中得出的任何结论——例如“似乎偏爱安静的颜色”——写入推断部分，形式为 `- [추론] #tag … — YYYY-MM-DD`，并作为代理的解读展示给本人。证据：带标记的条目。
5. **提升。** 对检查显示的每个候选（三份不同的简报；同一份简报内的重复只算一次），展示其信号并询问：提升、搁置还是放弃。只有选择提升时，才写 `- #tag <本人的句子> — 승격 YYYY-MM-DD · 근거 [[a]] [[b]] [[c]]`。绝不因为一次醒目的反应就提升。证据：本人的选择，以及检查通过。
6. **表达。** 本人说出某样东西应当是什么样子时，先写或更新原语，再写技法：一段用他们的话写成的文字、一个只按名称引用原语的 YAML 块、层，以及承载判断的关系（边缘比页面更亮；文字在玻璃上以 4.5:1 可读，大字以 3:1 可读）。对没有产品契约的作品（幻灯片、海报、报告），技法可以把角色命名为派生值 — `text.primary: color.ink`、`accent: color.accent` — 这样简报就能指向角色；组件的值仍归产品契约。运行 `python3 -m kb taste expression <expression.md> --show`，并把计算出的值念回给本人。证据：0 个问题和这些值。
7. **下一步。** `python3 -m kb skills next design.taste`：要开始一项依托这些条目的工作时用 design.brief，或什么都不做。

## 借口与反驳

| 想法 | 反驳 |
|---|---|
| “他们显然很喜欢这个；我就把它写成他们的品味。” | 一次反应只是信号。品味是在三件不同的作品中都成立的东西，由本人来提升。 |
| “我能从参考看出他们的风格。” | 那是推断。带标记写下，展示出来，让他们纠正。 |
| “十六进制值比名称更清楚。” | 原始值会掩盖判断。给原语命名，并写下使它成立的关系。 |
| “给这个人只留一份品味文件，更简单。” | 品味是在项目或品牌的情境中判断的。共用的笔记会把为不同对象所做的判断混在一起。 |
| “他们否决了；原因显而易见。” | 去问。原因才使否决可以复用。 |

## 警示信号

- 没有提升日期，或背后的简报不足三份的品味条目。
- 写在推断部分之外或没有标记的代理推断。
- 被转述而不是被引用的信号。
- 使用原始颜色值或没有关系的技法。
- 为某个人而不是某个项目或品牌建立的品味笔记。

## 验证

- `python3 -m kb taste check <taste.md>` 报告 0；已展示候选，本人对每一个都做了选择。
- 对涉及的每种技法，`python3 -m kb taste expression <expression.md>` 报告 0。
- 每一条新条目都是本人的话或其认可的文字，并已念回给本人。
