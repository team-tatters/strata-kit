# strata.verify

## 概述

用证据取代“完成了”的印象。证据在运行测试、检查器或构建的那一刻记录，在声称完成的那一刻比对：如果其间任务文件有变动，证据就已过时，需要重新运行命令。建立一张表：负责的技能要求了什么、什么能证明每一项、哪些无法验证，然后给出通过或不通过的结论。

## 适用场景

在任何完成报告、合并请求或“完成”声明之前；被问到某个东西是否能用时；一旦出现“应该能行”或“看起来对”的时候。不因改动很小而跳过。

## 流程

1. 收集负责技能和任务的 validation 项。证据：清单。
2. 通过记录器运行产生证据的命令（测试、检查器、构建），并列出任务改动的文件：`python3 "$STRATA_KIT/tools/verify_evidence.py" record --files <任务文件或目录> -- <命令>`。记录器会显示输出、原样返回命令的退出码，并在 `.strata/local/verify/<会话>.yaml` 中追加一条记录（命令、退出码、时间、输出末尾、所列文件的内容哈希）。未指定 `--session` 时，会话为最新的按会话活动文件。只列出本任务的文件：同一检出目录可能有其他会话在编辑。证据：带退出码的输出和证据文件路径。
3. 报告前运行 `python3 "$STRATA_KIT/tools/verify_evidence.py" check`。每条命令的最新记录会显示通过或失败、最新或过时（附带改动的文件）。过时的命令重新运行；失败的是不通过项。证据：check 的输出。
4. 填表：项目、证据（check 的那一行，若在 CI 则引用该次运行）、已验证或附原因的未验证。
5. 给出通过或不通过的结论。只要有一个 must 项未验证或其证据过时，就是不通过。交接中写 `tests_passed: true` 时要注明证据文件。 变更新增或改变的行为必须由已提交的测试实际执行；一次性命令只是手动检查，不是完成的证据——在该测试存在之前，将该项标为未验证并声明 no-go。

当问题不是一个任务而是整个项目时（strata 是否真的在这个项目中运行 — 检查器的安装与运行、生成指引是否最新、决定是否已提交、修改核心原本的 solo 决定、librarian 的最近一次运行），运行 `python3 "$STRATA_KIT/tools/doctor.py" <项目>`（只读，`--json` 输出相同条目）。default 和 block 条目按上面的 must 条目计算，参考条目只报告（DEC-2026-10-31-22·28）。

## 借口与反驳

| 想法 | 反驳 |
|---|---|
| “测试我刚才跑过了。” | 刚才的结果是否仍然有效，由 `check` 判断。过时就现在重跑。 |
| “记录太麻烦，直接跑命令就行。” | 有了记录，结论才能事后核对；压缩之后的自己和下一个会话都会读它。 |
| “只改了一行。” | 一行改动也会弄坏构建。表格三行就够。 |
| “这里跑不了。” | 那就写“未验证”，并写明什么能验证它。不要声称已完成。 |

## 警示信号

- 没有表格的完成报告。
- 完成消息里出现“应该能用”。
- 只有描述、没有输出的测试。
- 没有证据文件的 `tests_passed: true`，或表格引用了 `check` 判为过时的证据。

## 验证

- 表格完整。
- 对所引用的命令，`check` 返回 0（最新且通过），否则该项引用外部运行。
- 已给出通过或不通过的结论。
