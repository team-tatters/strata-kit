# strata.distill

## 概要

書かれたものではなく、学んだことを、業務用 vault から個人のコアへ移します。業務側には候補レコードを、個人側には元の文脈なしでも成り立つように書き直したパターンまたはガイドを作ります。

## 使う場面

セッションの終わり、または再利用できるものが生まれたときの依頼で。すべてのセッションに候補があるわけではありません。理由を添えた「なし」も有効な結果です。

## 手順

1. 教訓を、プロジェクトから独立した問題と判断として名づけます。証拠: 一文。
2. 業務用 vault に候補レコードを書きます: id、元のリビジョン、対象ノート id、status。証拠: そのレコード。
3. 個人コアのドキュメントを書く、または更新します: 問題、選択肢とトレードオフ、条件、反例、検証、合成した例。証拠: そのドキュメント。
4. ガード(名前、ドメイン、パス、添付ファイル)を実行し、その結果を自分で読みます。証拠: ガードの出力。
5. 候補を applied にします。同じ id での再実行は、重複を作らず更新にならなければなりません。

## 言い訳と反論

| 考え | 反論 |
|---|---|
| 「もう書いてあるから、ドキュメントをそのままコピーすればよい。」 | コピーには会社の文脈が付いてきます。一般的な部分だけを書き直してください。 |
| 「ガードを通ったから、きれいだ。」 | 文字列チェックは名前を捕まえますが、形は捕まえません。部外者として読んでください。 |
| 「プロジェクトの最後に蒸留しよう。」 | 教訓は薄れます。それを学んだセッションで蒸留してください。 |

## 警告サイン

- 唯一の出典として会社のパスを引用している個人コアのドキュメント。
- 一つの候補 id に対して二つのドキュメントがあること。
- 対象 id のない候補。

## 検証

- 候補レコードが完全である。
- ドキュメントが単独で成り立ち、ガードを通過して、その結果を読んだ。
- 再実行が冪等である。
