# strata.handoff

## 概述

写出让下一个会话无需本次对话也能继续的交接：做了什么（附证据）、什么尚待处理及原因、记录了哪些决策、需要留意什么，以及哪些内容要提炼进个人核心。然后将记录、验证和发布作为三个独立步骤来完成。

## 适用场景

会话结束时、任务边界处、拆分或压缩之前，或应要求时。写多少由工作模式（using-strata）决定：只读不写交接；单会话仅在仍有待处理事项时写；多会话和编排在每次会话结束时都写。

## 流程

1. 记录：写下 completed（附文件和证据）、in_progress（每项的 blocker 和 unblocked_by）、decisions_made（DEC id）、判断过程（问过用户什么、怎么答的，被推翻的判断及原因，几行即可，写在同名一节 — DEC-2026-10-30-03）、事实与假设（已确认的事实及用什么确认、未确认的推测、已放弃的假设及放弃理由 — 因对话超过令牌警戒线或同一假设的尝试两次受阻而以重启信号结束的会话必须填写；DEC-2026-10-31-11，session-splitting 5.1）、warnings、next_session。证据：交接文件。
2. 主线：填写 orders 和 kb_updates 链接。证据：frontmatter。
3. 提炼：列出要提炼进个人核心的候选，或写“无”并附理由。证据：候选部分。
4. 记忆：运行 `python3 -m kb hygiene --memory`，查看本会话写入或修改的记忆条目。对进行状态类条目（手头的工作、下一步、未提交、受阻之处），提议移到本交接的 in_progress 或 warnings；对人确认仍然正确的条目，把 `verified` 改为今天。从记忆中移除是移动之后另行询问的问题：只针对人逐条批准的条目，方式是把文件移到 `_archive/`、写上 `retired` 和 `retired_reason` 并删去索引行，绝不直接删除（context-protocol 第 7 节，DEC-2026-10-31-16·17）。证据：提议和人的回答，或“本会话未写入记忆”。
5. 验证：运行覆盖率关卡、链接检查、未提交记录检查。证据：输出。把关卡输出的“无规格的变更代码 N · 候选 M · 需要新规格 K”（连同需要自身规格的模块）一行写进交接；这些 covers 候选在 projects/<project>/_meta/covers-candidates.yaml（source: impact）中等待，经人批准并运行 `python3 -m kb hygiene --covers-apply` 后才写入。若本会话改的是知识（概念、政策、决定）而不是代码，关卡还会列出“需复查的代码（advisory）”——同一主题节点下规格的 covers 和被取代决定的 affects；在交接中写明复查了什么，或为何没有复查。 关卡等级未解决时（FAIL·BLOCK 行——脚本会在交接开头和 stderr 留下“no-go”行），不以完成关闭会话：编写规格（strata.kb-update），或在 Tier P 的 gate-overrides.yaml 中留下理由和期限，并在交接中写明做了哪一项（DEC-2026-10-29-08）。
6. 发布：只暂存列出的路径（交接、ledger、镜像），并通过会话结束通道提交；如实报告推送成功或失败。 若远端已前进，绝不在本会话未写的文件上执行 rebase 或 autostash：在临时克隆中把本会话的提交放到远端最新之上再推送，或停下并报告重叠。 提交前先阅读项目的提交规则：列出项目根目录，阅读 AGENTS.md、CLAUDE.md 以及那里的规则或笔记文件（README、CONTRIBUTING、名称形如 *NOTES*、*RULES* 的文件）；若项目或用户的规则与 harness 的默认指示（如署名 trailer 等 attribution）不同，则遵循项目或用户的规则。

## 借口与反驳

| 想法 | 反驳 |
|---|---|
| “待办项写‘等待用户’就够了。” | 等什么，什么能解除阻塞？两者都要写，否则这一项会永远滚动下去。 |
| “我把 vault 里所有改动都提交。” | 只提交本会话的路径。其他会话的改动不该由你发布。 |
| “这次没什么可提炼的。” | 写“无”并说明原因。没有也是一种信息。 |

## 警示信号

- 待办项没有 blocker。
- 发布时暂存了不是你写的文件。
- 交接没有 next_session 的值。

## 验证

- 待办项完整。
- 关卡输出在回复中。
- 已列出发布的路径；推送状态属实。
