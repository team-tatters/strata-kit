# strata.kb-update

```yaml
skill:
  id: strata.kb-update
  version: '0.1'
  owner: builder
  triggers:
  - changed files are covered by a knowledge document
  - a coverage gate or debt notice fired
  - the user asks to update documentation
  inputs:
  - changed file list
  - covers mapping and node pages
  - the owning knowledge documents
  outputs:
  - updated knowledge document (update in place) with sources
  - 'or a doc_change: none declaration with reason'
  - regenerated indexes and node pages
  required_context:
  - rec.spec.desired-vs-as-built
  allowed_tools:
  - read
  - edit(knowledge documents)
  - bash(index build, link check)
  validation:
  - 'every changed covered path maps to an updated document or a doc_change: none reason'
  - the updated document's updated and sources fields changed
  - index and link check pass
  failure_modes:
  - 'no owning document exists for a changed contract: create a shape document or extend covers; do not leave it unowned'
```

## Overview

Keeps as-built knowledge equal to the code: finds the document that owns each changed path, updates it in place with sources, or records why no change is needed, then regenerates the generated views.

## When to use

After covered code changed; when a gate or debt notice fires; on request. Also to declare doc_change: none with a reason, which is a valid outcome.

## Process

1. List changed files and resolve their owning documents through covers. Evidence: the mapping.
2. For each owner: update the relevant section in place; set updated and sources. Evidence: the diff.
3. For paths with no owner: create a shape document or extend covers. Evidence: the new mapping.
4. Where the shape did not change: write doc_change: none with the reason. Evidence: the declaration.
5. Rebuild the index and run the link check. Evidence: outputs.

## Rationalizations

| Thought | Rebuttal |
|---|---|
| "The code change is internal, docs are unaffected." | Then declare doc_change: none with that reason. The gate needs the declaration, not the assumption. |
| "I will update the docs in the next session." | The next session does not know what changed. Update now or declare. |
| "A date stamp is enough." | A stamp without a content check is drift with a date on it. |

## Red flags

- Changed covered path with neither update nor declaration.
- A document updated without sources.
- Node pages regenerated by hand.

## Verification

- Mapping complete.
- Index and link check pass.
- Declarations have reasons.
