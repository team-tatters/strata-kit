# strata.security

## 개요

코어는 운영자에게 하루 한 장의 노트를 줍니다. 무엇이 새로 떴고, 무엇이 아직 열려 있고, 무엇이 닫혔고, 어느 대상을 아무도 보고 있지 않은지. 이 스킬은 그 노트의 사람 쪽입니다. 정기 작업이 쓴 것을 읽고, 사람의 판단을 파일로 되돌려 놓고(오더·수용된 리스크·문턱·연결), 사람이 새 실측값을 가져오면 대상 목록을 다시 만듭니다. 스스로 수집하거나 등급을 매기거나 패치하지 않습니다 — 수집과 등급은 정기 작업이 기록된 규칙으로 하고, 패치는 조건이 성립할 때만 `patch plan`·`patch run` 으로 합니다.

## 언제 쓰는가

노트를 읽는 일이 매일의 트리거입니다. 새로 지켜볼 것이 생겼을 때(서버·데스크탑·의존 파일), 어떤 취약점이 우리에게 닿는지 물을 때, 문턱이나 수용된 리스크를 정할 때도 씁니다. 사고 대응(operator 의 흐름)과 제품 자신의 결함 저장소에는 쓰지 않습니다.

## 절차

1. **그날의 노트를 읽는다.** `security/notes/<day>.md` 를 연다. 긴급 줄부터, 그다음 처음 뜬 날이 적힌 미조치, 그다음 눈이 없는 대상. 머리에 보지 못한 층이 있으면 다른 무엇보다 먼저 그것을 말한다. 증거: 노트 경로와 counts 줄.
2. **판단하기 전에 링크를 따라간다.** 손대는 항목마다 `security/matches/<day>.yaml` 의 레코드와 대조를 연다: 어떤 식별자로 맞았는지, 어떤 범위인지, 점수가 얼마이고 어느 원천(NVD·CNA·벤더)에서 왔는지, 다른 원천에서 채운 값인지. 증거: 레코드 id 와 대조 id.
3. **사람과 함께 분류한다.** 긴급 항목은 이미 오더가 있다(정기 작업이 만들고 기본 귀속은 infra) — 오더를 보이고 귀속만 묻는다(`assign`). 권고는 묻는다: 오더로 올릴지(`promote <match> --by`), 사유·기한을 적어 수용된 리스크로 둘지(`accept ... --until --by`), 노트에 남겨 둘지. 혼자 정하지 않는다. 증거: 명령 출력.
4. **눈이 없는 대상에 눈을 준다.** 대상마다 공지 자리(GitHub 저장소·벤더 페이지)를 사람에게 묻고 `security/sources.yaml` 의 수동 연결로 적는다. 잠금 파일이 없는 저장소는 필요한 SBOM 을 말한다. 증거: manual_links 줄.
5. **목록은 실측값으로 다시 만들고, 서버에서 만들지 않는다.** 사람이 `docker ps`·compose·`dpkg-query`·OS 버전을 붙이면 이미지·버전·패키지 이름만 남기고(환경 변수·비밀번호·해시는 뺀다) `security/registry.yaml` 이 가리키는 자리에 두고 `python3 -m kb security inventory --project <p> --env <e> --write` 로 차이를 보인다. 증거: 차이 출력.
6. **문턱은 명령으로만 바꾼다.** `python3 -m kb security grading set --project <p> [--env <e>] threshold <값> --by <사람>` — history 줄이 기록이다. 증거: history 항목.
7. **패치는 조건이 성립할 때만.** `patch plan <order>` 가 조건(코드 수준·다운타임 없음·수 분 내 교체·기록된 수락)을 말한다. `patch run` 은 조건 없이 거부한다. 수락이 필요한 실행은 사람의 수락이 오더에 먼저 기록돼야 한다. 증거: 오더의 계획과 실행 기록.

## 합리화

| 생각 | 반박 |
|---|---|
| "제목이 원격 코드 실행이니 긴급으로 올리자." | 등급은 점수와 기록된 문턱에서 온다. 점수가 없으면 no-score 사유의 권고다 — 보이되 올리지 않는다. |
| "KEV 에 있으니 긴급이다." | KEV 는 노트의 정렬이고 등급은 아니다(DEC-02). 문턱 아래면 권고다. |
| "내가 ssh 로 들어가 버전을 확인하자." | 에이전트는 서버에 들어가지 않는다. 사람에게 명령 출력을 받는다. |
| "compose 파일에 버전이 있으니 그대로 저장하자." | 비밀번호도 있다. 이미지·버전만 남기고 무엇을 뺐는지 말한다. |
| "사람이 바쁘니 이 리스크는 내가 수용해 두자." | 수용된 리스크는 사람의 것이고 사유·기한이 있다. 노트에 남겨 둔다. |

## 적신호

- 파일에서 손으로 고친 등급이나 문턱.
- 기한이 없거나 에이전트가 기록한 수용된 리스크.
- 세션에서 실행한 서버 명령.
- 비밀이 든 compose·환경 파일이 vault 에 복사된 것.
- 이름만으로 CVE 에 맞춘 눈이 없는 대상.

## 검증

- 모든 행동이 그날 노트의 줄 또는 대조 id 를 가리킨다.
- 목록을 바꾼 뒤 `python3 -m kb security inventory --all` 이 exit 0.
- grading.yaml 의 history 가 바꾼 만큼만 늘었고, accepted-risks.yaml 행마다 reason·until·by 가 있다.
- 서버나 제품 자신의 흐름에 손대지 않았다.
