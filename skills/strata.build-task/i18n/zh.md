# strata.build-task

## 概述

执行一个任务：阅读任务携带的规格，只在一个层内修改指定的文件，运行验证命令，并连同证据和逐条约束的遵守情况报告完成。

## 适用场景

被分配了来自 strata.order 的任务文件，或用户要求实现一项已规划的变更。没有任务时不适用：不完整的任务会被拒绝，并列出缺失项。

## 流程

1. 阅读任务并检查其是否完整（层、文件、约束、验证）。证据：检查清单。不完整则拒绝。即使拒绝，也要先阅读指定的文件及其指向的文档，把缺失的决定列为带选项和推荐的具体问题；阅读不是猜测，实现才是。然后认领该订单（`python3 -m kb order claim <order-id>`）；若已被其他机器或会话认领，则停下来询问负责人。证据：认领输出。
2. 阅读指定的文件以及同一模式的一个现有示例。证据：路径。
3. 当任务新增行为时，先写失败的测试，再写最少的代码，然后重构。证据：前后的测试输出。
4. 运行任务的验证命令和层检查器。证据：输出和退出码。
5. 报告：改动的文件、约束遵守情况表、证据、任何未验证的事项。

## 借口与反驳

| 想法 | 反驳 |
|---|---|
| “任务差不多完整了，其余的我可以推断。” | 推断正是跨层的由来。拒绝并索要缺失项。 |
| “代码写完再补测试也行。” | 先失败的测试，才证明这个测试确实测到了东西。 |
| “检查器的警告是误报。” | 把它作为警告连同你的理由一起报告；不要压掉它。 |

## 警示信号

- 编辑了任务中未指明的文件。
- 报告里没有命令输出。
- 某条约束被标为已遵守却没有理由。

## 验证

- 验证命令的输出在报告中。
- 只有该层内的文件被改动。
- 约束遵守情况表完整。
