# using-strata

## 概述

`using-strata` 是入口技能。它只做两件事：输出会话当前所处的位置（让用户和智能体共享同一组事实），并把任务路由到负责它的技能。它从不亲自做具体工作，自身也从不改变；扩展来自分层注册表，而不是这个文件。

## 适用场景

- 每个会话开始时，先于任何回应，包括澄清问题、代码库搜索或读取文件。提问也是任务。
- 任务形态发生变化时：功能开发中途收到缺陷报告、收到部署请求、收到更新文档的请求。
- 如果你是作为子智能体被派去执行某个具体任务，则不适用：此时遵循该任务，忽略本技能。

## 流程

1. **读取项目清单。** 打开项目根目录下的 `.strata/profile.yaml`。如果缺失，停下并调用 `strata.init-wizard`。证据：清单路径及其 `project` 值。
2. **仅在没有头部时分层加载注册表。** 如果启动钩子已输出 strata 头部，该头部已经展示了当前生效的 must 建议卡片和注册表每一层的状态。直接使用它，不要重新打开宪章和注册表全文。第 5 步的路由匹配依据框架列出的技能描述进行；只有当头部显示某个配置文件层或项目层有自己的路由时，才打开该层的注册表文件。没有头部时，执行以下操作。先读 strata-kit 的 `skills/registry.yaml`，再读配置文件注册表，最后读项目注册表（向导生成的 `.strata/kit/registry.yaml`，项目有技能包时再加 Tier P 的 `skills/registry.yaml`）。逐个打开文件；某一层的文件不存在时，要说明该层“不存在”，而不是跳过。后面的层追加路由，并按 `skill` 覆盖前面的层。同时打开本技能 `required_context` 中的每个文件（即宪章），不要依赖它的摘要。证据：路由列表及每条路由来自哪一层，以及已打开的 required_context 路径。 用户层（`~/.strata/skills`：kit 的包在 `packs/`，人自己写的技能在 `local/`）在配置文件之后、项目之前读取。用户层只添加路由——其他层已有同名的会被拒绝，唯一例外是用 `overrides:` 写明要替换的核心技能的 local 技能，头部会显示它（`python3 -m kb skills check`，DEC-2026-10-31-36）。
3. **输出上下文头。** 包括领域（工作或个人）、项目 id 及别名、配置文件 id、当前生效的 must 建议卡片（仅 id）、被豁免的 should 建议卡片及其理由，以及来自最新交接或 active-task 文件的下一步行动。如果启动钩子已输出头部，就重新展示该头部并加上工作模式，不要从文件重新组装。如果活动文件和交接都读不到（变量未设置、工具被拒、文件不存在），先说明这一点，在询问进度之前先读仓库自身的痕迹 —— NOTES、HANDOFF 之类的笔记文件、`git log`、分支。头部会显示查找过的位置。证据：回复中的头部，位于一切内容之前。
4. **确定工作模式。** 如果框架已指定模式（Quilt piece 会在指令中写明其模式），就使用它。否则自行选择：只读（调查、提问、评审；不改变文件或外部状态）、单会话（在本会话内完成的改动）、多会话（跨会话的工作：已有或将有订单）、编排（多个会话或角色并行工作）。义务：只读只需头部和路由，没有活动文件和交接；单会话需要写明 `mode` 和 `harness_session_id`（harness 的会话 id，Claude Code 为 `CLAUDE_CODE_SESSION_ID`，头部和压缩后的恢复靠它找到本会话的文件）的活动文件、验证证据、决策记录，仅在仍有待处理事项时写交接；多会话在此之上还需要订单和每次会话结束时的交接；编排在此之上还需要按角色的权限策略、注入任务文件的约束以及评审包。只读会话要改变状态时，先升级为单会话。决策记录和状态变更前的确认适用于所有模式。证据：头部中的模式。
5. **将任务匹配到路由。** 把请求与所请求语言环境下的触发条件比较，回退到 `en`。只要有路由可能适用，就指出它。若有多个适用，流程类技能（`strata.spec`、`strata.order`）先于实现类技能（`strata.build-task`）。证据：路由及一行理由。
6. **调用该技能。** 宣告“因为 <理由>，使用 <技能>”，并严格遵循。为该技能的每个检查清单项创建一个待办。如果读完后发现该技能不适合，要如实说明并回到第 5 步。

## 借口与反驳

| 想法 | 反驳 |
|---|---|
| “这只是个简单的问题。” | 提问也是任务。输出上下文头并路由。只需读一次。 |
| “检查技能之前我需要更多上下文。” | 技能检查先于上下文收集；技能会告诉你该收集什么上下文。 |
| “我记得这个技能写了什么。” | 技能会随核心修订而变化。读当前版本。 |
| “这个改动用不着技能，小题大做。” | 小改动会变成大改动。路由成本很低；跳过检查点代价很高。 |
| “既然是只读，头部可以省略。” | 只读省掉的是文件，不是头部。展示 must 建议卡片的正是头部。 |
| “用户很着急。” | 上下文头只有五行。错误的路由比输出它花的时间多得多。 |

## 警示信号

- 回复以答案或行动开头，没有上下文头。
- 工作在没有指明技能、也没有说明理由的情况下推进。
- 会话在没有 `.strata/profile.yaml` 的项目中编辑文件。
- 头部中列出的 must 建议卡片被后续步骤绕着争辩。
- 只读会话没有先升级为单会话就编辑文件。

## 验证

在继续进入被路由的技能之前，确认以下全部事项，并用一行说明：

- 头部最先输出，并写明项目 id 和配置文件。
- 已读取注册表各层或由启动钩子头部给出，并指明了路由（或“无，因为……”）。
- 已说明工作模式。
- 被路由技能的 `required_context` 列表已加载。
