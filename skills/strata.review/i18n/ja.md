# strata.review

## 概要

会話全体を共有せずに、新しいコンテキストから独立したチェックを得ます。決定、ポインタ優先の証拠、範囲を絞った依頼からなる構造化パケットを使い、往復は一回で、回答のトリアージを記録します。

## 使う場面

自明でない決定、契約に触れる変更、または依頼があったとき。すべての編集に使うものではありません。パケットはレビュアーのコンテキストを消費します。

## 手順

1. レビュアーが必要とするものに応じて、レベル(0 ポインタ、1 要約、2 決定と証拠、3 差分、4 全体)を選びます。証拠: レベルと理由。
2. パケットを書きます: 決定のアンカー、path:lines 形式の証拠、一つか二つの不足点に限った依頼、未解決の質問。証拠: パケットファイル。
3. 作業中のセッションではないレビュアーのセッションに送ります。往復は一回です。証拠: リレーの記録。
4. 回答をそのまま添付し、トリアージします: accept、revise、escalate。レビューが作業セッションの外(別のモデル・人・クロスレビュー)から来た場合は、vault の projects/<project>/reviews/<日付>-<slug>.md に type review のレビュー記録も書きます。review_of(レビュー対象の revision)・received・source を記し、「対応の要約」節(受け入れ・反論・報告になかった発見・ユーザーの決定・生じた決定とオーダー)と原文そのままの「原文」節を置きます(DEC-2026-10-30-03)。証拠: 理由付きのトリアージとレビュー記録のパス。
5. 回答によって決定が変わった場合は、strata.decision で記録します。

## 言い訳と反論

| 考え | 反論 |
|---|---|
| 「自分のコンテキストの中で聞けばいい。」 | あなたのコンテキストにはあなたの前提が入っています。新しいコンテキストであることが要点です。 |
| 「漏れがないように、会話全体を送ろう。」 | 会話全体は問いを埋もれさせます。ポインタ優先の証拠と、範囲を絞った依頼にしてください。 |
| 「レビュアーが賛成したから、終わりだ。」 | トリアージを記録してください。記録のない賛成は証拠ではありません。 |

## 警告サイン

- 依頼のないパケット。
- 自動的に繰り返される複数回の往復。
- 添付する前に編集されたレビュアーの出力。

## 検証

- パケットが完全である。
- 往復が一回である。
- トリアージが記録されている。
