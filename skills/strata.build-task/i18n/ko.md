# strata.build-task

## 개요

태스크 하나를 실행합니다. 태스크가 담은 명세를 읽고, 한 레이어 안의 지정된 파일만 바꾸고, 검증 명령을 돌리고, 증거와 제약별 준수 여부와 함께 완료를 보고합니다.

## 언제 쓰는가

strata.order 의 태스크 파일이 할당됐거나 사용자가 계획된 변경의 구현을 요청할 때 씁니다. 태스크 없이는 쓰지 않습니다. 불완전한 태스크는 빠진 항목을 적어 반려합니다.

## 절차

1. 태스크를 읽고 완전한지(레이어·파일·제약·검증) 확인합니다. 증거: 체크리스트. 불완전하면 반려합니다. 반려하더라도 지정된 파일과 그 파일이 가리키는 문서는 먼저 읽고, 빠진 결정을 선택지와 추천이 있는 구체적인 질문으로 적습니다. 읽는 것은 추측이 아니고, 구현하는 것이 추측입니다. 그다음 오더를 선점합니다(`python3 -m kb order claim <order-id>`). 다른 머신이나 세션이 잡고 있으면 멈추고 사람에게 묻습니다. 증거: 선점 출력.
2. 지정된 파일과 같은 패턴의 기존 예시 하나를 읽습니다. 증거: 경로.
3. 동작을 더하는 태스크면 실패하는 테스트를 먼저 쓰고, 최소 코드를 쓰고, 다듬습니다. 증거: 전후 테스트 출력.
4. 태스크의 검증 명령과 레이어 검사기를 돌립니다. 증거: 출력과 종료 코드.
5. 보고합니다. 바꾼 파일, 제약 준수 표, 증거, 검증하지 못한 것.

## 합리화

| 생각 | 반박 |
|---|---|
| "태스크가 거의 완전하니 나머지는 추론하면 된다." | 추론이 레이어를 넘게 만듭니다. 반려하고 빠진 항목을 요청하세요. |
| "테스트는 코드 뒤에 써도 된다." | 실패하는 테스트가 그 테스트가 무언가를 시험한다는 증거입니다. |
| "검사기 경고는 오탐이다." | 근거와 함께 경고로 보고하세요. 끄지 마세요. |

## 적신호

- 태스크에 없는 파일의 수정.
- 명령 출력이 없는 보고.
- 이유 없이 준수로 표시된 제약.

## 검증

- 검증 명령 출력이 보고에 있다.
- 레이어 안의 파일만 바뀌었다.
- 제약 준수 표가 완전하다.
