# スキル標準

strata-kit のスキルは、エージェントが従うワークフローであり、ざっと目を通す参考資料ではありません。`core/schemas/skill.schema.yaml` のスキーマが形を定めます。このページでは、各部分がなぜ存在するのか、どう書くのかを説明します。

## 構成

```text
skills/<name>/
├── SKILL.md            English canonical: frontmatter + yaml block + six sections
├── i18n/ko.md …        localized bodies, same section order
├── evals/              pressure scenarios and results (RED / GREEN / REFACTOR)
├── references/         long material the body links to
└── scripts/            bundled tools, run through their interpreter
```

## フロントマター

`name` は、ハーネスが照合するフラットな識別子です。コアのスキルは `strata.<verb>` で、入口のスキルは `using-strata` です。

`description` は、エージェントがスキルを開くかどうかを決める前に目にする唯一のものです。「Use when」で始まり、状況、症状、キーワードを列挙します。ワークフローを要約してはいけません。要約を読んだエージェントは本文ではなく要約に従ってしまい、チェックポイントがあるのは本文だからです。

## yaml ブロック

H1 の直後に、`id`、`version`、`owner`、`triggers`、`inputs`、`outputs`、`required_context`、`allowed_tools`、`validation`、`failure_modes` を持つ、フェンス付きの `yaml` ブロックを置きます。これは本文の機械可読な対であり、ジェネレーターはこれを読んでアダプターとレジストリを作ります。`validation` は「検証」セクションと一対一に対応します。

## 六つのセクション

1. **概要**: 一段落で、このスキルが何を生み出すかを書きます。
2. **使う場面**: トリガーと、明示的な非トリガー。
3. **手順**: 番号付きのステップ。各ステップは、チェックポイントと、それが残す証拠(ファイル、コマンド出力、レコード id)を明示します。
4. **言い訳と反論**: エージェントがステップを飛ばすときに使う言い訳(「これはちょっとした変更だから」「ルールは覚えている」)と、それぞれへの反論。エージェントは既定で最短の道を取ります。このセクションはそれに対する重しです。
5. **警告サイン**: スキルが飛ばされている、または誤って適用されていることを示す観察可能な兆候。レビュアーやゲートが検出できるように書きます。
6. **検証**: スキルが完了を報告してよくなる前に、何が成り立っていなければならないか、そしてそれを何の証拠で示すか。「合っていそう」は決して証拠ではありません。

## エージェントのための書き方

- エージェントが承知のうえで飛ばすステップには禁止を書きます。抜けがちなものには、必須の欄があるテンプレートを使います。条件に依存する振る舞いには条件分岐を使います。
- ニュアンスを含む節は書きません。「重要でない限り X をしない」は交渉を再開させます。本当の例外は、別々の条件分岐として書いてください。
- `SKILL.md` は 300 行未満に保ちます。長い参考資料は `references/` に置いてリンクします。そうすれば、必要になるまでそのスキルが使うトークンは少なくて済みます。
- 完全に実行できる例が一つあるほうが、断片的な例が三つあるより効果的です。

## スキルのテスト

スキルを書くことは、プロセスに適用したテスト駆動開発です。そのスキルを持たないサブエージェントで `evals/` のシナリオを実行し、何を飛ばし、それをどう正当化したかを記録します(RED)。それらの失敗に対処する最小限のスキルを書き、もう一度実行します(GREEN)。見つかった抜け道を塞いで、もう一度実行します(REFACTOR)。シナリオ、トランスクリプトの要約、判定を `evals/` に残します。RED の実行が記録されていないスキルは、下書きです。

## ローカライズ

翻訳するのは本文だけです。yaml ブロック、フロントマター、すべての識別子は英語のままにします。スキルが `active` になる前に、`en` と `ko` が必要です。残りの四つのロケールは、警告付きで英語にフォールバックします(`LOCALES.md` を参照)。
