# ideation.shape

## 概要

アイデアは完成するずっと前から役に立ちます。このスキルは、アイデアを使える状態まで整理するのを手伝います。使う場所は企画・仕様・決定・振り返りのどこでも構いません。アイデアを代わりに作ることはしません。アイデア一つはノート一枚で、五つの属性(発端・問題・方法・結果・意味)を持ちます。空欄は許され、空欄が次の問いになります。エージェントはアイデアにまだ必要な条件とオーダーの数を予測し、本人に確認してもらいます。確認された数がそのアイデアの重さで、開いているアイデアの重さの合計が、本人が抱えている悩みの総量です。アイデアは制限なく育てられます。30日を超えて成長のないアイデアにはアーカイブを提案し、削除はしません。

問いの立て方と行き詰まったときの道具は jwynia/agent-skills `brainstorming` v1.1(MIT)に従います。状態を兆候・問い・介入で書く形式を受け継ぎ、元の発散プロトコルはここでは骨格ではなく道具です。

## いつ使うか

本人がアイデアを持ち出したとき、攻めたい問題や具体化したい直感があるとき、行き詰まったときに使います。要件の作成(strata.spec)や、すでに下した決定の記録(strata.decision)には使いません。この二つは次の流れの候補です。本人の代わりにアイデアを出すためにも使いません。対話だけの間は読み取り専用で、アイデアノートを書く・育てるときに単一セッションへ上がります(DEC-2026-11-01-18)。

## 手順

1. **持ち出す。** `python3 -m kb ideas list` を実行し、似た開いているアイデアと既存のアプローチを探します(`python3 -m kb search "<本人の言葉>" --hybrid`)。あるものと悩みの総量を示し、「これが寄りかかれる既存のものは何か」と問います。選択肢は三つ: 新しいノート、既存ノートに追加、今開いているものを強化してこれはメモだけ残す。証拠: 一覧と本人の選択。
2. **性格。** はっきりした問題・現象を攻めるのか、ぼんやりした直感を具体化したいのかを問います。問題型は問題から始めて結果・方法へ、直感型は意味と発端から始めます。証拠: ノートの `nature`。
3. **五つの属性。** 一つずつ問います: 何を解決するか(問題)、何を得たいか(結果)、何に意味を置くか(意味)、そのために何をするか(方法)、どこから始まったか(発端)。本人の言葉を書きます。まだ答えられない欄は「비어 있음」と書きます。方法の欄が埋まっているのに問題か結果が空なら、形に縛られた状態です。「何を達成しなければならないか、この方法はその一つか」と問います。証拠: ノートの属性節。
4. **条件と重さ。** アイデアが成り立つために真であるべき条件と、必要なオーダー数を予測します。最小実験も条件になりえます。予測を示し、直すか確認してもらいます。その後にだけ `conditions`・`orders_expected`・`weight_confirmed` を書きます。証拠: 本人の確認。
5. **広げる・絞る・消去する。** 空欄を検索語にして参照を探し、一つずつ出典とともに示します。候補が増えたらアプローチ別にまとめ、まとまりごとに代表一つと最小実験を問います。対象を広げるか絞るか、どう消去するかは本人が選びます。硬い消去は不明確なものを消して残りに集中します。柔らかい消去はすべて整理したうえでつながりで圧縮します。属性を埋めている間は評価せず、消去は本人が選んだときだけ行います。消去した事例と理由はノートに書きます。アイデア同士の距離は `python3 -m kb ideas near <ノート> [--embed]` が属性ごとに示し、関係の候補(代替・転用・束ね・競合)とその値、リンク候補、近傍の偏りの一行も出します。`python3 -m kb ideas map <ノート> [--facet 属性]` はそのアイデアを中心に置いた Obsidian キャンバスを書きます。どちらもノートを変えません。本人が選んだリンクだけを足し、それぞれ `link` イベントを残します。証拠: 消去した事例の節。
6. **行き詰まったとき。** どの選択肢も変形に見えるなら、兆候から状態を診断し、合う道具だけを使います。収束盲目なら、ありきたりな案を先に書き出します。機能固定なら、何を(WHAT)とどうやって(HOW)を分けます。軸の崩壊なら、誰が・いつ・規模・方法のどれかを回します。領域への閉じこもりなら `python3 -m kb ideas draw --note <ノート>` で衝突材料を引きます(アイデアのプロジェクト外の記録が先、足りなければ制約リスト)。材料が何とぶつかるかを問い、何が見えるかは本人が書きます。証拠: 示した材料と本人の言葉。
7. **成長の記録と締めくくり。** 属性を埋める、リンクを足す、別の流れで使う、条件が満たされる、そのたびに `python3 -m kb ideas event <ノート> facet|link|use|condition "<何が>"` を実行します(アーカイブされたノートは再び開きます)。次に `python3 -m kb skills next ideation.shape` を実行して候補をそのまま示し、「何もしない」も含めます。選ぶのは本人です。選んだものはアクティブファイルとハンドオフの判断過程の節に書きます。証拠: イベント行と本人の選択。

## ノート形式

`$STRATA_VAULT/ideas/<YYYY-MM-DD>-<slug>.md`、`python3 -m kb ideas check` で点検します:

```markdown
---
title: "<本人の言葉で書いたアイデア>"
type: idea
created: YYYY-MM-DD
nature: problem | intuition
status: active | archived
projects: [<関連プロジェクト>]
conditions:
  - {text: "<条件>", met: false}
orders_expected: 2
orders_done: 0
weight_confirmed: YYYY-MM-DD
---

# <タイトル>

## 발단
## 문제
## 방법
## 결과
## 의미
## 소거한 사례
## 발전 기록

- YYYY-MM-DD facet — <育ったこと>
```

アーカイブ(`python3 -m kb ideas tidy --apply`、既定はプレビュー)は `status: archived` と `archived: {date, reason}` だけを変えます。ノートはその場に残ります。

## 合理化

| 考え | 反論 |
|---|---|
| 「例のアイデアがいくつかあれば始めやすい。」 | それではノートに自分のアイデアが入ります。材料と問いを渡し、見えたことは本人が書きます。 |
| 「空欄は明らかだから埋めておこう。」 | 空欄は次の問いです。埋めると本人が見るべき隙間が隠れます。 |
| 「重さはどうせ推定だから書いておこう。」 | 確認された重さだけが悩みの総量に入ります。先に問います。 |
| 「このアイデアは明らかに企画に進む番だ。」 | 流れは提案です。「何もしない」を含む候補を示し、本人に選んでもらいます。 |
| 「このアイデアは進んでいないから消そう。」 | アーカイブするだけで消しません。半分できた直感は、あとで欠けた一片に出会えます。 |

## 危険信号

- 本人が言っていない、または承認していない属性の文。
- 属性を埋めている途中でアイデアを評価する。
- `weight_confirmed` のない重さ。
- 問題にも結果にも役立たない新しさ。
- 既存のアプローチを調べずに一からアイデアを出す。
- 「逆にする」を発散とみなす — 同じ軸の上にとどまります。

## 検証

- ノートが `python3 -m kb ideas check` を通る。
- すべての属性の文と重さが、このセッションの本人の言葉にさかのぼれる。
- 変わったことごとに成長イベントが記録された。
- 次の流れは本人が候補から選んだ。
