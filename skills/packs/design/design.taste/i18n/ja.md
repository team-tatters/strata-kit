# design.taste

## 概要

好みとは判断の記録であり、エージェントが選ぶスタイルではありません。このスキルは、一つのプロジェクトまたは一つのブランドについてその記録を保ちます — 本人全体のための記録は作りません。好みは、作業が置かれた文脈の中で判断されるものだからです(DEC-2026-11-01-10)。好みのノートには四つの節があります: 好み(本人が昇格させた行)、シグナル(反応と選択)、推論(エージェントが推測したもの、印付き)、却下(本人が断ったものとその理由)。三つの異なるブリーフに現れたタグは昇格の候補になり、決めるのは本人です。表現のノートは、その好みがどう見えるかを書きます: プリミティブ(色、ぼかし、不透明度、余白、角丸、書体)は一度だけ書き、各技法は読める段落と、レイヤーと関係(OKLCH の明度での明るく・暗く、不透明度、WCAG コントラスト)を記した YAML ブロックにします。その値を `kb taste expression` が計算します(DEC-2026-11-01-11)。

手順は skeltonmedia/design-taste-skills(MIT。パックの NOTICE を参照。Taste Skill とは別のリポジトリ)に倣っています: 参照を巡るインタビュー、却下の記録、繰り返されたシグナルだけの昇格、推論への印付け。ここにある文章と検査は strata 独自のものです。

## 使う場面

本人がデザインしながら何かに反応しているとき、プロジェクトやブランドの好みを書き留める、または見直す必要があるとき、技法を検査できる形で書く必要があるとき。ブリーフそのもの(design.brief)や、製品のトークンやコンポーネント契約には使いません — それは実装による置き換えの仕事です。好みのノートを読むのは読み取り専用で、シグナル・推論・技法を書くときに単一セッションへ上がります(DEC-2026-11-01-18)。

## 手順

1. **ノートを探す。** どのプロジェクトまたはブランドのためのものかを尋ねます。その好みのノートと表現のノートを開くか、パックの例から作ることを提案します。`python3 -m kb taste check <taste.md>` を実行し、候補を示します。証拠: パスと検査の出力。
2. **インタビュー、一度に一つの質問。** 参照ごとに、最初に何に気づいたか、その中の何がそう感じさせるのか、ここに合うかを尋ねます。答えをシグナルとして書きます: `- YYYY-MM-DD 반응|고름 #tag [[brief]] — "本人の言葉"`。本人が参照ではなく価値(ブランドの中核的な価値や「信頼」のような言葉)から始めるときは、五つの軸 — 形、色、感情、質感、物 — を枠組みにし、軸ごとに連想を一つと目に見える手がかりを一つ尋ねます。本人が挙げた手がかりはシグナル、エージェントが足した連想は推論です。互いにぶつからない三つほどのキーワードへの絞り込みは本人とだけ行い、二つがぶつかるなら、どちらが中心で、どちらが小さなアクセントの割合にとどまるかを尋ねます(DEC-2026-11-01-13)。証拠: 新しいシグナルの行を本人に読み返したもの。
3. **却下。** 本人が何かを断ったら、理由を尋ねて `- YYYY-MM-DD #tag [[brief]] — "本人の言葉" — 이유: …` と書きます。理由のない却下は、まだ開いたままの問いです。証拠: 却下の行。
4. **推論。** シグナルからエージェントが導いたこと — たとえば「落ち着いた色を好むようだ」 — は、`- [추론] #tag … — YYYY-MM-DD` として推論の節に入れ、エージェントの読みとして本人に示します。証拠: 印付きの行。
5. **昇格。** 検査が示す候補ごと(三つの異なるブリーフ。一つのブリーフ内の繰り返しは一回と数える)に、そのシグナルを示して尋ねます: 昇格、保留、破棄。昇格のときだけ `- #tag <本人の文> — 승격 YYYY-MM-DD · 근거 [[a]] [[b]] [[c]]` と書きます。一度の印象的な反応から昇格させてはいけません。証拠: 本人の選択と、検査の通過。
6. **表現。** 本人が何かをどう見せたいかを言葉にしたら、プリミティブを書くか更新し、続いて技法を書きます: 本人の言葉による段落、プリミティブを名前だけで参照する YAML ブロック、レイヤー、そして判断を支える関係(縁はページより明るい。ガラスの上で文字は 4.5:1、大きな文字は 3:1 で読める)。製品契約のない作業(スライド、ポスター、レポート)では、技法がロールを導出値として名付けてもよい — `text.primary: color.ink`、`accent: color.accent` — そうすればブリーフはロールを指せます。コンポーネントの値は製品の契約に残ります。`python3 -m kb taste expression <expression.md> --show` を実行し、計算された値を読み返します。証拠: 問題 0 件と、その値。
7. **次へ。** `python3 -m kb skills next design.taste`: これらの行に基づく作業を始めるなら design.brief、または何もしない。

## 言い訳と反論

| 考え | 反論 |
|---|---|
| 「明らかにこれが大好きだ。本人の好みとして書こう。」 | 一度の反応はシグナルです。好みとは、三つの異なる作業にわたって成り立つもので、昇格させるのは本人です。 |
| 「参照を見れば、その人のスタイルはわかる。」 | それは推論です。印を付けて書き、示して、本人に直してもらってください。 |
| 「名前より 16 進の値のほうがわかりやすい。」 | 生の値は判断を隠します。プリミティブに名前を付け、それを正しくしている関係を書いてください。 |
| 「本人用に好みのファイルを一つにしたほうが簡単だ。」 | 好みはプロジェクトやブランドの文脈で判断されます。共有のノートは、別々のもののための判断を混ぜてしまいます。 |
| 「断ったのだから、理由は明らかだ。」 | 尋ねてください。理由があるから却下を再利用できます。 |

## 警告サイン

- 昇格日がない、または裏付けのブリーフが三つ未満の好みの行。
- 推論の節の外にある、または印のないエージェントの推論。
- 引用せず言い換えられたシグナル。
- 生の色の値がある、または関係のない技法。
- プロジェクトやブランドではなく、人のための好みのノート。

## 検証

- `python3 -m kb taste check <taste.md>` が 0 を報告する。候補を示し、本人が一つずつ選んだ。
- 触れたすべての技法について `python3 -m kb taste expression <expression.md>` が 0 を報告する。
- 新しい行はすべて本人の言葉か本人が承認した文で、本人に読み返した。
