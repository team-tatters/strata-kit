# strata.decision

## 개요

아키텍처 결정을 decision writer 로 같은 세션 안에 영속 레코드로 남기고, 결정이 이 프로젝트를 넘어 일반화되면 권고 카드 후보를 뽑습니다.

## 언제 쓰는가

지속되는 선택이 내려지거나 발견되는 순간에 씁니다. 계약을 건드리지 않고 나중에 되돌릴 수 있는 지역적 구현 선택에는 쓰지 않습니다.

## 절차

1. 결정을 한 문장으로, 이유와 검토한 대안을 적습니다. 증거: 그 텍스트.
2. topic·decision·reason·affects 로 decision writer 를 실행합니다. 검토한 대안은 하나씩 --alternative '대안: 진 이유' 로, 참고한 개념·자료는 --background 로 넘겨, 나중의 회고가 고르지 않은 것을 볼 수 있게 합니다(DEC-2026-10-30-03). 증거: DEC id 와 재생성된 인덱스 경로.
3. 이전 레코드를 대체하면 supersede 를, 철회하면 withdraw 를 실행합니다. 증거: CLI 출력.
4. 결정이 일반화되면 카드 후보(주장·강도·근거=이 DEC)를 backlog 에 적습니다. 증거: 후보 경로.
5. 핸드오프의 decisions_made 에 DEC id 를 넣습니다.

## 합리화

| 생각 | 반박 |
|---|---|
| "세션 끝에 기록하겠다." | 세션은 갑자기 끝납니다. 지금 기록하세요. 명령 하나입니다. |
| "뻔한 결정이라 레코드가 필요 없다." | 다음 세션은 당신이 아닙니다. 레코드는 그들을 위한 것입니다. |
| "인덱스를 직접 고치면 된다." | 인덱스는 생성물입니다. 손으로 고치면 덮어써지고 레코드를 잃습니다. |

## 적신호

- DEC id 없이 대화에만 있는 결정.
- 손으로 고친 인덱스.
- 대체된 규칙이 아직 현행으로 인용됨.

## 검증

- 답변에 DEC id 가 있다.
- CLI 가 인덱스를 재생성했다.
- 핸드오프 decisions_made 가 갱신됐다.
