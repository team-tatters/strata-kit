# ideation.shape

## 개요

아이디어는 완성되기 훨씬 전부터 쓸모가 있습니다. 이 스킬은 사용자가 아이디어를 쓸 수 있는 상태로 정리하도록 돕습니다. 쓸 곳은 기획·명세·결정·회고 어디든 됩니다. 아이디어를 대신 만들지는 않습니다. 아이디어 하나는 노트 한 장이고, 다섯 속성(발단·문제·방법·결과·의미)을 갖습니다. 빈칸은 허용하며, 빈칸이 다음 질문이 됩니다. 에이전트는 아이디어에 아직 필요한 조건과 오더의 수를 예측해 사용자에게 확인을 받습니다. 확인된 수가 그 아이디어의 무게이고, 열린 아이디어 무게의 합이 사용자가 지고 있는 고민의 총량입니다. 아이디어는 제한 없이 키울 수 있습니다. 30일 넘게 발전이 없는 아이디어는 아카이브를 제안하고, 지우지 않습니다.

질문 방식과 막혔을 때의 도구는 jwynia/agent-skills `brainstorming` v1.1(MIT)을 따릅니다. 상태를 증상·질문·개입으로 적는 형식을 받았고, 원본의 발산 프로토콜은 여기서 뼈대가 아니라 도구입니다.

## 언제 쓰는가

사용자가 아이디어를 꺼낼 때, 공략하고 싶은 문제나 구체화하고 싶은 직관이 있을 때, 막혔을 때 씁니다. 요구사항 작성(strata.spec)이나 이미 내린 결정의 기록(strata.decision)에는 쓰지 않습니다. 이 둘은 다음 흐름 후보입니다. 사용자 대신 아이디어를 내는 데도 쓰지 않습니다. 대화만 하는 동안은 읽기 전용이고, 아이디어 노트를 쓰거나 키우면 단일 세션으로 올라갑니다(DEC-2026-11-01-18).

## 절차

1. **꺼내기.** `python3 -m kb ideas list` 를 실행하고, 비슷한 열린 아이디어와 이미 있는 접근을 찾습니다(`python3 -m kb search "<사용자의 말>" --hybrid`). 있는 것과 고민의 총량을 보이고 "이것이 기댈 수 있는 이미 있는 것은 무엇인가"를 묻습니다. 선택지는 셋입니다: 새 노트, 기존 노트에 더하기, 지금 열린 것을 강화하고 이건 적어만 두기. 증거: 목록과 사용자의 선택.
2. **성격.** 분명한 문제·현상을 공략하는지, 흐린 직관을 구체화하려는지 묻습니다. 문제형은 문제에서 시작해 결과·방법으로, 직관형은 의미와 발단에서 시작합니다. 증거: 노트의 `nature`.
3. **다섯 속성.** 하나씩 묻습니다: 무엇을 해결하는가(문제), 무엇을 얻으려는가(결과), 무엇에 의미를 두는가(의미), 그것을 위해 무엇을 하는가(방법), 어디서 시작됐는가(발단). 사용자의 말을 적습니다. 아직 답하지 못한 칸은 "비어 있음"으로 적습니다. 방법 칸은 찼는데 문제나 결과 칸이 비어 있으면 형태에 묶인 상태입니다. "무엇을 달성해야 하는가, 이 방법은 그중 하나인가"를 묻습니다. 증거: 노트의 속성 절.
4. **조건과 무게.** 아이디어가 성립하려면 참이어야 할 조건과 필요한 오더 수를 예측합니다. 최소 실험도 조건이 될 수 있습니다. 예측을 보이고 사용자에게 고치거나 확인해 달라고 합니다. 그다음에만 `conditions`·`orders_expected`·`weight_confirmed` 를 적습니다. 증거: 사용자의 확인.
5. **넓히기·좁히기·소거.** 빈칸을 검색어로 삼아 레퍼런스를 찾고, 하나하나 출처와 함께 보입니다. 후보가 쌓이면 접근별로 묶고 묶음마다 대표 하나와 최소 실험을 묻습니다. 대상을 넓힐지 좁힐지, 어떻게 소거할지는 사용자가 고릅니다. 단단한 소거는 불명확한 것을 지우고 남은 것에 집중합니다. 부드러운 소거는 모두 정리한 뒤 연결고리로 압축합니다. 속성을 채우는 동안에는 평가하지 않고, 소거는 사용자가 고를 때만 합니다. 소거한 사례와 이유는 노트에 적습니다. 아이디어 사이의 거리는 `python3 -m kb ideas near <노트> [--embed]` 가 속성마다 보이고, 관계 후보(대안·전용·묶음·경쟁)와 그 값, 링크 후보, 이웃 치우침 한 줄을 함께 냅니다. `python3 -m kb ideas map <노트> [--facet 속성]` 은 그 아이디어를 가운데 둔 옵시디언 캔버스를 씁니다. 둘 다 노트를 바꾸지 않습니다. 사용자가 고른 링크만 더하고, 하나마다 `link` 사건을 남깁니다. 증거: 소거한 사례 절.
6. **막혔을 때.** 모든 선택지가 변형처럼 보이면 증상으로 상태를 진단하고 맞는 도구만 씁니다. 수렴 맹목이면 뻔한 안을 먼저 적습니다. 기능 고정이면 무엇(WHAT)과 어떻게(HOW)를 나눕니다. 축 붕괴면 누가·언제·규모·방식 중 하나를 돌립니다. 영역 갇힘이면 `python3 -m kb ideas draw --note <노트>` 로 충돌 재료를 뽑습니다(아이디어의 프로젝트 밖 기록이 먼저, 기록이 모자라면 제약 목록). 재료가 무엇과 부딪히는지 묻고, 무엇이 보이는지는 사용자가 적습니다. 증거: 보인 재료와 사용자의 말.
7. **발전 기록과 마무리.** 속성을 채우거나, 링크를 더하거나, 다른 흐름에서 쓰거나, 조건이 충족될 때마다 `python3 -m kb ideas event <노트> facet|link|use|condition "<무엇>"` 을 실행합니다(아카이브된 노트는 다시 열립니다). 그다음 `python3 -m kb skills next ideation.shape` 를 실행해 후보를 그대로 보이고, "아무것도 안 함"도 포함합니다. 고르는 것은 사용자입니다. 고른 것은 활성 파일과 핸드오프 판단 과정 절에 적습니다. 증거: 사건 줄과 사용자의 선택.

## 노트 형식

`$STRATA_VAULT/ideas/<YYYY-MM-DD>-<slug>.md`, `python3 -m kb ideas check` 로 점검합니다:

```markdown
---
title: "<사용자의 말로 쓴 아이디어>"
type: idea
created: YYYY-MM-DD
nature: problem | intuition
status: active | archived
projects: [<관련 프로젝트>]
conditions:
  - {text: "<조건>", met: false}
orders_expected: 2
orders_done: 0
weight_confirmed: YYYY-MM-DD
---

# <제목>

## 발단
## 문제
## 방법
## 결과
## 의미
## 소거한 사례
## 발전 기록

- YYYY-MM-DD facet — <자란 것>
```

아카이브(`python3 -m kb ideas tidy --apply`, 기본은 미리보기)는 `status: archived` 와 `archived: {date, reason}` 만 바꿉니다. 노트는 그 자리에 둡니다.

## 합리화

| 생각 | 반박 |
|---|---|
| "예시 아이디어 몇 개면 시작이 쉬워진다." | 그러면 노트에 내 아이디어가 담깁니다. 재료와 질문을 주고, 보이는 것은 사용자가 적습니다. |
| "빈칸이 뻔하니 채워 두자." | 빈칸은 다음 질문입니다. 채우면 사용자가 봐야 할 빈틈이 가려집니다. |
| "무게는 어차피 추정이니 적어 두자." | 확인된 무게만 고민의 총량에 들어갑니다. 먼저 묻습니다. |
| "이 아이디어는 분명 기획으로 갈 차례다." | 흐름은 제안입니다. "아무것도 안 함"을 포함한 후보를 보이고 사용자가 고르게 합니다. |
| "이 아이디어는 진척이 없으니 지우자." | 아카이브할 뿐 지우지 않습니다. 반쯤 된 직감은 나중에 빠진 조각을 만날 수 있습니다. |

## 적신호

- 사용자가 말하거나 승인하지 않은 속성 문장.
- 속성을 채우는 중에 아이디어를 평가함.
- `weight_confirmed` 없는 무게.
- 문제나 결과에 쓰이지 않는 새로움.
- 이미 있는 접근을 찾아보지 않고 처음부터 아이디어를 냄.
- "반대로 하기"를 발산으로 여김 — 같은 축 위에 머뭅니다.

## 검증

- 노트가 `python3 -m kb ideas check` 를 통과한다.
- 모든 속성 문장과 무게가 이 세션의 사용자 말로 거슬러 올라간다.
- 바뀐 것마다 발전 사건이 기록됐다.
- 다음 흐름은 사용자가 후보에서 골랐다.
