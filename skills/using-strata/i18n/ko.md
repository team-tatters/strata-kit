# using-strata

## 개요

`using-strata` 는 진입점입니다. 두 가지만 하고 다른 일은 하지 않습니다. 세션이 어디에 있는지를 출력해서 사용자와 에이전트가 같은 사실을 공유하게 하고, 작업을 그 작업을 맡는 스킬로 보냅니다. 일을 직접 하지 않고, 이 파일 자체는 바뀌지 않습니다. 확장은 이 파일이 아니라 겹쳐 읽는 레지스트리에서 옵니다.

## 언제 쓰는가

- 모든 세션의 시작, 어떤 응답보다도 먼저. 확인 질문, 코드베이스 검색, 파일 읽기보다도 먼저입니다. 질문도 작업입니다.
- 작업의 모양이 바뀔 때마다. 기능 작업 중에 들어온 버그 보고, 배포 요청, 문서 갱신 요청이 그렇습니다.
- 특정 작업 하나를 실행하라고 서브에이전트로 파견된 경우에는 쓰지 않습니다. 그때는 받은 작업을 따르고 이 스킬은 무시합니다.

## 절차

1. **프로젝트 매니페스트를 읽습니다.** 프로젝트 루트의 `.strata/profile.yaml` 을 엽니다. 없으면 멈추고 `strata.init-wizard` 를 호출합니다. 증거: 매니페스트 경로와 `project` 값.
2. **헤더가 없을 때만 레지스트리를 겹쳐 읽습니다.** 시작 훅이 strata 헤더를 출력했으면 그 헤더가 적용 중인 must 카드와 레지스트리 층마다의 상태를 이미 보여 줍니다. 그것을 쓰고, 헌법과 레지스트리 전문을 다시 열지 않습니다. 5단계의 경로 맞추기는 하네스가 보여 주는 스킬 설명으로 하고, 헤더에 자기 경로가 있는 프로필·프로젝트 층이 보일 때만 그 레지스트리 파일을 엽니다. 헤더가 없으면 다음을 합니다. strata-kit 의 `skills/registry.yaml`, 그다음 프로필 레지스트리, 그다음 프로젝트 레지스트리(마법사가 쓴 `.strata/kit/registry.yaml`, 프로젝트에 스킬 팩이 있으면 Tier P 의 `skills/registry.yaml`)를 읽습니다. 파일을 하나씩 열고, 층의 파일이 없으면 건너뛰지 말고 그 층을 "없음" 이라고 말합니다. 뒤 층이 경로를 더하고 같은 `skill` 이름은 덮어씁니다. 이 스킬의 `required_context`(헌법)도 요약에 기대지 말고 직접 엽니다. 증거: 경로 목록과 각 경로가 온 층, 그리고 연 required_context 경로. 사용자 층(`~/.strata/skills`: kit 의 팩은 `packs/`, 사람이 만든 스킬은 `local/`)은 프로필 다음, 프로젝트 앞에 읽습니다. 사용자 층은 경로를 더하기만 합니다. 다른 층에 같은 이름이 있으면 거부되고, 예외는 `overrides:` 로 바꿀 코어 스킬을 적은 local 스킬뿐이며 헤더가 그것을 보입니다(`python3 -m kb skills check`, DEC-2026-10-31-36).
3. **컨텍스트 헤더를 출력합니다.** 영역(업무 또는 개인), 프로젝트 ID 와 별칭, 프로필 ID, 적용 중인 must 카드(ID 만), 해제된 should 카드와 사유, 최신 핸드오프나 active-task 파일에서 읽은 다음 행동. 시작 훅이 헤더를 출력했으면 그 헤더를 다시 보이고 작업 모드를 더합니다. 파일에서 다시 조립하지 않습니다. 활성 파일도 핸드오프도 읽을 수 없으면(변수 미설정·도구 거부·파일 없음) 그렇다고 말하고, 일이 어디까지 왔는지 묻기 전에 저장소 자체의 흔적 — NOTES·HANDOFF 같은 노트 파일, `git log`, 브랜치 — 을 읽습니다. 헤더가 어디를 찾아봤는지 보여 줍니다. 증거: 답변 맨 앞의 헤더.
4. **작업 모드를 정합니다.** 하네스가 정해 주었으면(Quilt piece 는 지시문에 모드를 적습니다) 그것을 씁니다. 아니면 고릅니다: 읽기 전용(조사·질문·리뷰, 파일이나 외부 상태를 바꾸지 않음), 단일 세션(이 세션에서 끝나는 변경), 여러 세션(세션을 넘는 작업, 오더가 있거나 생길 것), 오케스트레이션(여러 세션·역할이 병렬로 일함). 의무: 읽기 전용은 헤더와 경로 지정만, 활성 파일과 핸드오프는 없습니다. 단일 세션은 `mode` 와 `harness_session_id`(하네스 세션 ID, Claude Code 는 `CLAUDE_CODE_SESSION_ID` — 헤더와 컴팩션 복원이 이 세션의 파일을 찾는 고리)를 적은 활성 파일, 검증 증거, 결정 기록, 미결이 남을 때만 핸드오프. 여러 세션은 여기에 오더와 세션마다 핸드오프. 오케스트레이션은 여기에 역할별 권한 정책, 태스크 파일에 주입한 제약, 리뷰 패킷. 읽기 전용 세션이 상태를 바꾸려 하면 먼저 단일 세션으로 올라갑니다. 결정 기록과 상태 변경 전 확인은 모든 모드에 적용됩니다. 증거: 헤더의 모드.
5. **작업을 경로에 맞춥니다.** 요청을 요청된 로케일의 트리거와 비교하고, 없으면 `en` 으로 폴백합니다. 어느 경로든 그럴듯하게 해당하면 그 이름을 댑니다. 여럿이면 과정 스킬(`strata.spec`, `strata.order`)이 구현 스킬(`strata.build-task`)보다 먼저입니다. 증거: 경로와 한 줄 이유.
6. **스킬을 호출합니다.** "<이유> 때문에 <스킬> 을 씁니다" 라고 알리고 그대로 따릅니다. 그 스킬의 체크리스트 항목마다 할 일을 만듭니다. 읽어 보니 맞지 않으면 그렇게 말하고 5단계로 돌아갑니다.

## 합리화

| 생각 | 반박 |
|---|---|
| "그냥 간단한 질문인데." | 질문도 작업입니다. 헤더를 출력하고 경로를 정하세요. 읽기 한 번이면 됩니다. |
| "스킬을 확인하기 전에 맥락이 더 필요해." | 스킬 확인이 맥락 수집보다 먼저입니다. 어떤 맥락을 모을지는 스킬이 알려 줍니다. |
| "이 스킬 내용은 기억하고 있어." | 스킬은 코어 revision 과 함께 바뀝니다. 현재 판을 읽으세요. |
| "이 변경에 스킬은 과해." | 작은 변경은 큰 변경이 됩니다. 라우팅은 싸고, 체크포인트를 건너뛰는 것은 비쌉니다. |
| "읽기 전용이니 헤더는 생략해도 돼." | 읽기 전용이 빼는 것은 파일이지 헤더가 아닙니다. must 카드를 보여 주는 것이 헤더입니다. |
| "사용자가 급해 해." | 헤더는 다섯 줄입니다. 잘못된 경로가 그보다 더 많은 시간을 씁니다. |

## 적신호

- 컨텍스트 헤더 없이 답이나 행동으로 시작하는 응답.
- 스킬 이름도 이유도 없이 진행되는 작업.
- `.strata/profile.yaml` 이 없는 프로젝트의 파일을 고치는 세션.
- 헤더에 적힌 must 카드를 뒤의 단계가 우회하려고 논쟁하는 것.
- 단일 세션으로 올라가지 않고 파일을 고치는 읽기 전용 세션.

## 검증

경로로 정해진 스킬로 넘어가기 전에 다음을 모두 확인하고 한 줄로 말합니다.

- 헤더를 맨 먼저 출력했고 프로젝트 ID 와 프로필이 적혀 있다.
- 레지스트리 층을 읽었거나 시작 훅 헤더가 보여 주었고, 경로(또는 "없음, 이유는 …")를 말했다.
- 작업 모드를 말했다.
- 정해진 스킬의 `required_context` 목록을 읽었다.
