# Locales — six-language policy

strata-kit carries six locales from the start: `en`, `ko`, `ja`, `zh`, `es`, `fr`.

## What is translated, and what is not

| Kind of text | Treatment |
|---|---|
| Machine-facing identifiers: card ids, profile ids, skill names, YAML keys, enum values (`must`/`should`/`may`), tool and command names | Never translated. English only. |
| Human text inside YAML (card `claim`, `reason`, `applies_when`, role `duty`, wizard questions) | A locale map on the field: `claim: { en: "...", ko: "...", ja: "...", zh: "...", es: "...", fr: "..." }` |
| Skill `description` (the trigger text an agent matches) | English canonical in `SKILL.md`. Localized bodies live in `skills/<name>/i18n/<locale>.md`; adapters emit the body the harness language asks for. |
| Long-form documents (`core/docs`, profile READMEs, constitution rendering) | One file per locale: `docs/<locale>/<slug>.md`. The English file is canonical. |
| Code comments, commit messages, log strings | Follow the project convention; not part of the locale policy. |

## Authoring and parity rules

- Author in any of the six languages. Before a card or skill becomes `active`, `en` and `ko` must both exist (strength `must`); `ja`, `zh`, `es`, `fr` should exist (strength `should`) and fall back to `en` with a warning until they do.
- `tools/i18n_check.py` enforces parity: every locale map has the same keys, placeholders (`{name}`) match across locales, ids and enums are identical, and every `docs/en/*.md` has a sibling in each locale or an explicit `pending` marker in `i18n/pending.yaml`.
- Translations are generated by the `strata.translate` skill from the canonical text and then reviewed by a person. A translation never adds or removes a rule; if it must, the canonical text changes first.
- Terminology lives in `i18n/glossary.yaml` (one entry per term, six columns). Translators and the skill read it first.

## Literals that stay English

Values a tool parses stay English in every locale: frontmatter keys and values (`approved: true`, `doc_change: none`, `next: none`), status enums (`applied`, `active`, `must`), skill and card ids, the `Use when` prefix of a skill description. Human-readable table cells, announcements to the user ("using <skill> because <reason>") and prose are localized. When in doubt, keep the English literal in backticks and add the localized meaning in parentheses.

## Terms that are names, not words

`gate` (a check that can block), `guard` (the pre-export content check), `spine` (the handoff frontmatter links `orders`, `kb_updates`, `decisions_made`), `inline mode` (a small order without separate task files), `methodology backlog`, `session-end channel` (the record → verify → publish steps of strata.handoff), `ledger`, `harness` (Claude Code, Codex, Quilt) are glossary terms. Translate them with the glossary entry and keep the English in parentheses on first use in a document.

## Fallback order

`requested locale → en → ko`. A missing text is rendered from the fallback and flagged in the adapter output, never silently dropped.
