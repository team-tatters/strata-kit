# strata.retro

## 概述

回顾是为了本人的理解，而不是为了代理的效率。代理准备材料并提问；本人用自己的话解释之后，代理再指出记录说了什么、哪里是空白。结果是本人写的笔记；如果有值得带入方法论或决策的内容，就逐项交给负责它的技能。

## 何时使用

当本人想回顾过去的工作时：一周、一个订单、项目的一个阶段，或一个决策及其替代链。不用于检查工作是否完成（strata.verify），也不用于对变更做独立评审（strata.review）。在本人同意写笔记之前，工作模式是只读；写笔记时升为单会话。

## 步骤

1. **确定材料并生成资料包。** 与本人确定期间和项目，或作为起点的一个决策（它的替代链以及指向它的评审、会话——整个期间太多时用这个小资料包），必要时加节点或检索词。运行 `python3 -m kb retro-bundle --project P --from D --to D [--node N] [--query Q]` 或 `python3 -m kb retro-bundle --project P --decision DEC-id`。告诉本人文件夹位置和 `00-목차.md` 中的数量，并说明该文件夹可以原样上传到 NotebookLM。证据：文件夹路径和数量。
2. **让本人选择看什么。** 原样展示资料包 `00-목차.md` 中的条目列表：每个决策、评审、会话都附有记录中的事实（日期、节点、替代关系、关联的评审或决策）。询问从哪里开始。本人问某个条目讲什么时，从资料包中原文引用该条目的结论小节，并注明文件和标题。不总结、不排序，也不说哪一项做错了。证据：本人的选择。
3. **说任何话之前先提问。** 针对所选项目一次问一个问题：前提是什么，备选方案为什么落选，当时不知道而现在知道的是什么，现在会选什么、为什么。等本人用自己的话回答。证据：提出的问题。
4. **本人解释之后再指出记录。** 解释与记录不一致或记录空白之处（没有备选方案、没有背景、会话判断过程中被推翻的判断），引用资料包的文件和标题，并就该空白提问。不做"那是个好决策"之类的评价。证据：带出处的指出内容。
5. **征得同意后写学习笔记。** 询问是否保留笔记。若保留，说明会话升为单会话，并写 `$STRATA_VAULT/retrospectives/<YYYY-MM-DD>-<主题>.md`。frontmatter 为 `title`、`type: reference`、`created`、`tags: [retrospective, project/<p>]`、`source`（资料包条件）；三个小节：**回顾了什么**（资料包条件和所选项目）、**用我的话整理的理解**（本人的话，或本人逐行认可的文字）、**要移交的候选**（每个候选的去向和状态）。证据：笔记路径。
6. **移交本人确认的候选。** 在本项目之外也成立的经验交给 strata.distill，方法上的空白记入待办，现在会做出不同选择的决策交给 strata.decision 作替代。每一项都在本人同意之后。证据：每个候选调用的技能，或附理由的"无"。

## 自我合理化

| 想法 | 反驳 |
|---|---|
| "我看得出哪里错了，直接说能省时间。" | 这里的目标不是时间。建立理解的是本人自己的解释，代理的结论会取而代之。 |
| "先简要总结一下决策会有帮助。" | 总结就是对什么重要的判定。连同记录中的事实展示条目，被问到时原文引用结论，让本人选择。 |
| "理解一节我先起草，本人再改就行。" | 那样笔记就成了代理的。写本人的话，或本人逐行认可的文字。 |
| "这个候选显然该进待办，我先记上。" | 记入就是改变状态。先问，再交给负责的技能。 |

## 危险信号

- 第一次回复就评价、排序或总结这段时期。
- 指出记录却没有资料包的文件和标题。
- 理解一节读起来像代理文字的学习笔记。
- 本人未确认的待办项、提炼的模式或替代决策。

## 验证

- 按约定条件生成了资料包，并给出了数量。
- 提问先于指出，每次指出都有出处。
- 若写了笔记：本人同意，位于 retrospectives/，三个小节按上述格式填写。
- 每个移交的候选都经本人确认，并交给了负责的技能。
