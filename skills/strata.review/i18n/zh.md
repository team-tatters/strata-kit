# strata.review

## 概述

在不共享整个对话的前提下，从全新的上下文获得独立检查：一份结构化的包，包含决策、指针优先的证据和有界的请求，只往返一次，并对答复进行有记录的分流。

## 适用场景

用于重要的决策、触及契约的变更，或应要求时。不是每次编辑都用；这个包会消耗评审者的上下文。

## 流程

1. 按评审者所需选择级别（0 指针、1 摘要、2 决策 + 证据、3 diff、4 完整）。证据：级别及理由。
2. 写出这个包：决策锚点、以 path:lines 表示的证据、限定在一两个缺口内的请求、未决问题。证据：包文件。
3. 发送给不是当前工作会话的评审会话；只往返一次。证据：中继记录。
4. 原样附上答复并分流：接受、修订、上报。如果评审来自工作会话之外（另一个模型、人、交叉评审），还要在 vault 的 projects/<project>/reviews/<日期>-<slug>.md 写一份 type 为 review 的评审记录：写明 review_of（被评审的 revision）、received 和 source，包含“应对摘要”一节（接受、反驳、报告遗漏的发现、用户决定、由此产生的决策和订单）和原样保留的“原文”一节（DEC-2026-10-30-03）。证据：附理由的分流结果和评审记录路径。
5. 如果答复改变了某项决策，用 strata.decision 记录。

## 借口与反驳

| 想法 | 反驳 |
|---|---|
| “我就在自己的上下文里问一下。” | 你的上下文带着你的假设。关键就在于要全新的上下文。 |
| “把整个对话发过去，免得遗漏。” | 整个对话会淹没问题。要指针优先的证据和有界的请求。 |
| “评审者同意了，完事。” | 记录分流。没有记录的同意不是证据。 |

## 警示信号

- 包里没有请求。
- 自动进行多轮往返。
- 评审者的输出在附上之前被编辑过。

## 验证

- 包完整。
- 只往返一次。
- 分流已记录。
