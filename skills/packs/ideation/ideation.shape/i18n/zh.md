# ideation.shape

## 概述

想法在完成之前很久就已经有用。这个技能帮助本人把想法整理到可以使用的状态——用在规划、规格、决策或回顾中都可以——但不替本人产生想法。一个想法就是一张笔记,有五个属性(起因·问题·方法·结果·意义)。允许空栏,空栏就是下一个问题。代理预测这个想法还需要多少条件和多少次 order,并请本人确认;确认后的数字是这个想法的重量,所有开放想法的重量之和就是本人背负的思考总量。想法可以无限制地成长;超过 30 天没有成长的想法会被建议归档,从不删除。

提问方式和卡住时的工具遵循 jwynia/agent-skills `brainstorming` v1.1(MIT):把状态写成征兆·问题·干预的形式;原技能的发散协议在这里是工具,不是骨架。

## 何时使用

本人提出一个想法、一个想攻克的问题、一个想具体化的直觉,或者卡住时使用。不用于撰写需求(strata.spec)或记录已经做出的决定(strata.decision)——它们是下一步流程的候选。也不用于替本人产生想法。只进行对话时是只读;撰写或扩充创意笔记时升为单会话(DEC-2026-11-01-18)。

## 步骤

1. **提出。** 运行 `python3 -m kb ideas list`,并查找相似的开放想法和已有的做法(`python3 -m kb search "<本人的话>" --hybrid`)。展示已有的东西和思考总量,然后问:"这个可以建立在哪些已有的东西之上?"提供三个选择:新建笔记、加到已有笔记、加强已开放的想法并只把这个记下来。证据:列表和本人的选择。
2. **性质。** 问这个想法是攻克一个明确的问题或现象,还是要把模糊的直觉具体化。问题型从问题开始,再到结果和方法;直觉型从意义和起因开始。证据:笔记中的 `nature`。
3. **五个属性。** 一次问一个:要解决什么(问题),想得到什么(结果),本人在其中看重什么(意义),为此要做什么(方法),从哪里开始的(起因)。写下本人的话。本人暂时答不上的栏写作"비어 있음"。如果方法已填而问题或结果为空,说明想法被形式锁住:问"这必须达成什么?这个方法是其中一种做法吗?"证据:笔记的属性小节。
4. **条件与重量。** 预测想法成立所需为真的条件,以及需要多少次 order;最小实验也可以是一个条件。展示预测,请本人修改或确认。之后才写入 `conditions`、`orders_expected` 和 `weight_confirmed`。证据:本人的确认。
5. **放宽、收窄、消除。** 用空栏作为搜索词寻找参考,每条都附出处。候选堆积时,按做法分组,并就每组询问一个代表和一个最小实验。由本人选择放宽还是收窄目标,以及如何消除:硬消除(去掉不明确的,专注剩下的)或软消除(整理全部,再通过关联压缩)。填写属性时不做评价;只有本人选择时才消除。把被消除的案例和理由写进笔记。想法之间的距离由 `python3 -m kb ideas near <笔记> [--embed]` 按属性列出,并给出关系候选(替代·挪用·归并·竞争)及其数值、链接候选和一行邻近偏向;`python3 -m kb ideas map <笔记> [--facet 属性]` 写出以该想法为中心的 Obsidian 画布。两者都不改动笔记:只添加本人选中的链接,每条记一个 `link` 事件。证据:被消除案例小节。
6. **卡住时。** 如果每个选项都只是变体,根据征兆诊断状态,只用对应的工具:收敛盲区→先列出显而易见的选项;功能锁定→把做什么(WHAT)和怎么做(HOW)分开;轴塌缩→转动谁、何时、规模或方法之一;领域禁锢→用 `python3 -m kb ideas draw --note <笔记>` 抽取碰撞材料(先取想法所属项目之外的记录,记录不足时用约束列表)。问材料与什么碰撞;看到什么由本人写下。证据:展示的材料和本人的话。
7. **记录成长并收尾。** 每当填入属性、添加链接、在其他流程中使用或条件达成时,运行 `python3 -m kb ideas event <笔记> facet|link|use|condition "<内容>"`(已归档的笔记会重新打开)。然后运行 `python3 -m kb skills next ideation.shape`,原样展示候选,包括"什么都不做";由本人选择。把选择记录在活动文件和交接的判断过程小节中。证据:事件行和本人的选择。

## 笔记格式

`$STRATA_VAULT/ideas/<YYYY-MM-DD>-<slug>.md`,用 `python3 -m kb ideas check` 检查:

```markdown
---
title: "<用本人的话写的想法>"
type: idea
created: YYYY-MM-DD
nature: problem | intuition
status: active | archived
projects: [<相关项目>]
conditions:
  - {text: "<条件>", met: false}
orders_expected: 2
orders_done: 0
weight_confirmed: YYYY-MM-DD
---

# <标题>

## 발단
## 문제
## 방법
## 결과
## 의미
## 소거한 사례
## 발전 기록

- YYYY-MM-DD facet — <成长了什么>
```

归档(`python3 -m kb ideas tidy --apply`,默认为预览)只设置 `status: archived` 和 `archived: {date, reason}`;笔记留在原处。

## 合理化

| 想法 | 反驳 |
|---|---|
| "给几个示例想法能帮他们起步。" | 那样笔记里装的是你的想法。给材料和问题;看到什么由本人写。 |
| "这个空栏很明显,我来填上。" | 空栏是下一个问题。填上就遮住了本人该看的缺口。 |
| "重量只是估计,我先写上。" | 只有确认过的重量才计入思考总量。先问。 |
| "这个想法显然该进入规划了。" | 流程是建议。展示包括"什么都不做"在内的候选,让本人选择。 |
| "这个想法毫无进展,删掉吧。" | 只归档,不删除。半成形的直觉以后可能遇到缺失的那一块。 |

## 危险信号

- 本人没有说过或没有批准的属性句子。
- 在填写属性时评价想法。
- 没有 `weight_confirmed` 的重量。
- 不服务于问题或结果的新奇。
- 不查已有做法就从零开始构思。
- 把"反过来"当作发散——它仍在同一条轴上。

## 验证

- 笔记通过 `python3 -m kb ideas check`。
- 每个属性句子和重量都能追溯到本次会话中本人的话。
- 有变化的地方都记录了成长事件。
- 下一步流程由本人从候选中选出。
