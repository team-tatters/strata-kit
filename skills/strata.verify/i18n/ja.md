# strata.verify

## 概要

完了したという印象を、証拠に置き換えます。証拠はテスト・チェッカー・ビルドを実行した瞬間に記録し、完了を主張する瞬間に照合します。その間にタスクのファイルが変わっていれば証拠は古く、コマンドをもう一度実行します。担当スキルが要求したこと、それぞれを何が証明するか、検証できなかったことを表にまとめ、go か no-go かを述べます。

## 使う場面

完了報告、マージリクエスト、「できた」という主張の前。何かが動くかどうかを尋ねられたとき。「動くはず」や「合っていそう」という言葉が出たその瞬間。変更が小さいからといって省略してはいけません。

## 手順

1. 担当スキルとタスクの validation 項目を集めます。証拠：その一覧。
2. 証拠を生むコマンド（テスト、チェッカー、ビルド）を記録ツール経由で実行し、タスクが変更したファイルを指定します：`python3 "$STRATA_KIT/tools/verify_evidence.py" record --files <タスクのファイルまたはディレクトリ> -- <コマンド>`。記録ツールは出力を表示し、コマンドの終了コードをそのまま返し、`.strata/local/verify/<セッション>.yaml` に項目（コマンド、終了コード、時刻、出力の末尾、指定ファイルの内容ハッシュ）を追加します。`--session` を指定しなければ、セッションは最新のセッション別アクティブファイルです。このタスクのファイルだけを指定します。同じチェックアウトを別のセッションが編集している場合があります。証拠：終了コード付きの出力と証拠ファイルのパス。
3. 報告の前に `python3 "$STRATA_KIT/tools/verify_evidence.py" check` を実行します。コマンドごとの最新項目が、成功か失敗か、最新か古いか（変わったファイル付き）で表示されます。古いコマンドは再実行し、失敗したものは no-go 項目です。証拠：check の出力。
4. 表を埋めます。項目、証拠（check の行、CI ならその実行）、検証済み、または理由付きの未検証。
5. go か no-go かを述べます。must 項目が一つでも未検証か、証拠が古ければ no-go です。ハンドオフに `tests_passed: true` と書くときは証拠ファイルを併記します。 変更が追加・変更した振る舞いは、コミットされたテストが実際に実行しなければなりません。一回限りのコマンドは手動確認であって完了の証拠ではないため、そのテストができるまで項目を未検証とし no-go を宣言します。

問いがタスク一つではなくプロジェクト全体のとき（このプロジェクトで strata が実際に動いているか — 検査器の設置と実行、生成指針の現行性、決定のコミット、中核の原本を変えた solo 決定、librarian の最後の実行）は `python3 "$STRATA_KIT/tools/doctor.py" <プロジェクト>` を実行します（読み取り専用、`--json` は同じ項目）。default・block の項目は上の must 項目と同じに数え、参考項目は報告だけします（DEC-2026-10-31-22・28）。

## 言い訳と反論

| 考え | 反論 |
|---|---|
| 「テストはさっき実行した。」 | さっきの結果がまだ有効かは `check` が教えてくれます。古ければ今実行してください。 |
| 「記録は手間だ。コマンドだけ実行すればいい。」 | 記録があるから、主張を後で確かめられます。コンパクション後の自分も、次のセッションもそれを読みます。 |
| 「一行だけの変更だ。」 | 一行の変更でもビルドは壊れます。表は三行で済みます。 |
| 「ここでは実行できない。」 | それなら「未検証」と、何があれば検証できるかを書いてください。できたとは言わないでください。 |

## 警告サイン

- 表のない完了報告。
- 完了メッセージの中の「動くはず」。
- 出力がなく説明だけのテスト。
- 証拠ファイルのない `tests_passed: true`、または `check` が古いと報告する証拠を引用した表。

## 検証

- 表が完全である。
- 引用したコマンドについて `check` が 0 を返す（最新かつ成功）。そうでなければ、その項目が外部の実行を引用している。
- go か no-go かを述べた。
