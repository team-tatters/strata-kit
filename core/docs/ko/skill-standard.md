# 스킬 표준

strata-kit 의 스킬은 에이전트가 따르는 절차이지, 훑어보는 참고 문서가 아닙니다. 모양은 `core/schemas/skill.schema.yaml` 이 정하고, 이 문서는 각 부분이 왜 있는지와 어떻게 쓰는지를 설명합니다.

## 모양

```text
skills/<name>/
├── SKILL.md            영어 정본: frontmatter + yaml 블록 + 여섯 절
├── i18n/ko.md …        번역된 본문, 같은 절 순서
├── evals/              압력 시나리오와 결과 (RED / GREEN / REFACTOR)
├── references/         본문이 링크하는 긴 자료
└── scripts/            동봉 도구, 인터프리터로 실행
```

## Frontmatter

`name` 은 하네스가 매칭하는 평평한 식별자입니다. 코어 스킬은 `strata.<동사>` 이고 진입 스킬은 `using-strata` 입니다.

`description` 은 에이전트가 스킬을 열지 말지 정하기 전에 보는 유일한 것입니다. "Use when" 으로 시작해서 상황·증상·키워드를 나열합니다. 워크플로 요약은 절대 넣지 않습니다. 요약을 읽은 에이전트는 본문 대신 요약을 따르는데, 체크포인트는 본문에 있기 때문입니다.

## yaml 블록

H1 바로 뒤에 `id`, `version`, `owner`, `triggers`, `inputs`, `outputs`, `required_context`, `allowed_tools`, `validation`, `failure_modes` 를 담은 yaml 블록이 옵니다. 산문의 기계 판독용 쌍둥이이며, 생성기가 이것을 읽어 어댑터와 레지스트리를 만듭니다. `validation` 은 검증 절과 일대일로 대응합니다.

## 여섯 절

1. **개요**: 한 문단, 이 스킬이 무엇을 만드는가.
2. **언제 쓰는가**: 트리거와 명시적인 비트리거.
3. **절차**: 번호가 붙은 단계. 각 단계는 체크포인트와 남기는 증거(파일, 명령 출력, 레코드 ID)를 말합니다.
4. **합리화**: 에이전트가 단계를 건너뛸 때 쓰는 핑계("작은 변경이니까", "규칙을 기억하니까")와 각각의 반박. 에이전트는 기본으로 지름길을 가므로 이 절이 균형추입니다.
5. **적신호**: 스킬이 건너뛰어지거나 잘못 적용되고 있다는 관찰 가능한 신호. 검토자나 게이트가 감지할 수 있게 씁니다.
6. **검증**: 완료를 보고하기 전에 무엇이 참이어야 하고 어떤 증거가 그것을 증명하는가. "맞아 보인다" 는 증거가 아닙니다.

## 에이전트를 위해 쓰기

- 알면서 건너뛰는 단계에는 금지문을, 빠뜨리는 것에는 필수 칸이 있는 템플릿을, 조건에 따라 달라지는 행동에는 조건문을 씁니다.
- 뉘앙스 조항을 쓰지 않습니다. "중요하지 않으면 X 하지 마라" 는 협상을 다시 엽니다. 진짜 예외는 별도의 조건문으로 씁니다.
- `SKILL.md` 는 300줄 아래로 유지합니다. 긴 참고 자료는 `references/` 에 두고 링크해서, 필요할 때까지 토큰을 적게 쓰게 합니다.
- 완전하고 실행 가능한 예시 하나가 부분적인 예시 셋보다 낫습니다.

## 스킬 시험

스킬 작성은 절차에 적용한 테스트 주도 개발입니다. 스킬이 없는 서브에이전트에 `evals/` 의 시나리오를 돌려 무엇을 건너뛰고 어떻게 정당화했는지 기록합니다(RED). 그 실패를 다루는 최소 스킬을 쓰고 다시 돌립니다(GREEN). 발견된 빈틈을 막고 한 번 더 돌립니다(REFACTOR). 시나리오, 대화 요약, 판정을 `evals/` 에 둡니다. RED 기록이 없는 스킬은 초안입니다.

## 다국어

본문만 번역합니다. yaml 블록, frontmatter, 모든 식별자는 영어로 둡니다. 스킬이 `active` 가 되려면 `en` 과 `ko` 가 있어야 하고, 나머지 네 로케일은 경고와 함께 영어로 폴백합니다(`LOCALES.md` 참조).
