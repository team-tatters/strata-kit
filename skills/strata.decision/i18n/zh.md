# strata.decision

## 概述

在做出决策的同一个会话内，用决策记录写入工具把架构决策记录为持久的记录；当决策的意义超出本项目而具有普适性时，提取一张建议卡片候选。

## 适用场景

一旦做出或发现了一个持久的选择，就立刻记录。对于以后可以随时撤销、且不触及任何契约的局部实现选择，不适用。

## 流程

1. 用一句话陈述决策、理由以及考虑过的备选方案。证据：该文本。
2. 运行决策记录写入工具，带上 topic、decision、reason、affects。每个考虑过的备选方案用 --alternative '方案：落选原因' 传入，参考的概念或资料用 --background 传入，让日后的复盘看得到没有选的方案（DEC-2026-10-30-03）。证据：DEC id 和重新生成的索引路径。
3. 如果取代了先前的记录，运行 supersede；如果撤回，运行 withdraw。证据：CLI 输出。
4. 如果决策具有普适性，起草一张卡片候选（claim、强度、证据 = 此 DEC）放入待办库。证据：候选路径。
5. 把 DEC id 写入交接的 decisions_made。

## 借口与反驳

| 想法 | 反驳 |
|---|---|
| “我会在会话结束时再记录。” | 会话会突然结束。现在就记；只是一条命令。 |
| “这很明显，没人需要记录。” | 下一个会话的人不是你。记录是写给他们的。 |
| “我可以直接编辑索引。” | 索引是生成的。手工编辑会被覆盖，记录也会丢失。 |

## 警示信号

- 决策在聊天中陈述，却没有 DEC id。
- 索引被手工编辑过。
- 已被取代的规则仍被当作现行规则引用。

## 验证

- 回复中有 DEC id。
- 索引由 CLI 重新生成。
- 交接的 decisions_made 已更新。
