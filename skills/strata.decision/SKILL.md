# strata.decision

```yaml
skill:
  id: strata.decision
  version: '0.1'
  owner: builder
  triggers:
  - an architecture decision is made in conversation
  - a review resolves a disagreement with a lasting rule
  - an earlier decision is replaced or withdrawn
  inputs:
  - the decision, its reason, alternatives considered
  - affected files and cards
  - the decision writer CLI
  outputs:
  - a decision record (DEC id) written by the CLI; index and mirror regenerated
  - a candidate recommendation card when the decision generalizes
  - supersede or withdraw applied to the earlier record
  required_context:
  - rec.decision.record-immediately
  allowed_tools:
  - bash(decision writer CLI)
  - read
  validation:
  - the DEC id exists and the index was regenerated by the CLI, not by hand
  - affected paths are listed
  - a superseded record is marked by the CLI
  failure_modes:
  - 'the decision is really a task-level implementation choice: do not record; say so'
```

## Overview

Records an architecture decision as a durable record with the decision writer, in the same session it was made, and extracts a recommendation card candidate when the decision generalizes beyond this project.

## When to use

The moment a lasting choice is made or discovered. Not for local implementation choices that a later change can reverse without touching a contract.

## Process

1. State the decision in one sentence, the reason, and the alternatives considered. Evidence: the text.
2. Run the decision writer with topic, decision, reason, affects. Pass each alternative weighed as --alternative 'option: why it lost' and the concepts or sources consulted as --background, so a later retrospective can see what was not chosen (DEC-2026-10-30-03). Evidence: the DEC id and the regenerated index path.
3. If an earlier record is replaced, run supersede; if withdrawn, run withdraw. Evidence: the CLI output.
4. If the decision generalizes, draft a card candidate (claim, strength, evidence = this DEC) into the backlog. Evidence: the candidate path.
5. Put the DEC id into the handoff's decisions_made.

## Rationalizations

| Thought | Rebuttal |
|---|---|
| "I will record it at the end of the session." | Sessions end abruptly. Record it now; it is one command. |
| "It is obvious, nobody needs a record." | The next session is not you. The record is for them. |
| "I can edit the index directly." | The index is generated. Hand edits are overwritten and lose the record. |

## Red flags

- A decision stated in chat with no DEC id.
- An index edited by hand.
- A superseded rule still cited as current.

## Verification

- DEC id in the reply.
- Index regenerated by the CLI.
- Handoff decisions_made updated.
